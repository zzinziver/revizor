# /revizor:setup — настройка Ревизора

Аргументы команды: `$ARGUMENTS` (не нужны).

`ROOT` = `${CLAUDE_PLUGIN_ROOT}` (подставлен в командах). Команды — только `node "<путь>/scripts/<имя>.mjs" …`, пути в кавычках, прямые слэши, `timeout: 600000`, без синтаксиса оболочки. Файлы настроек сам не правь: их пишет `doctor.mjs`. Кракозябры в выводе — запусти ту же команду с `--json`.

Первая строка человеку: «Проверю окружение, задам 3–4 вопроса и предложу правила разрешений — это несколько минут. Потом по желанию — пробная проверка на демо-сайте: она дольше, сколько займёт — скажу перед запуском».

## 1. Окружение
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.mjs" --json
```
- **`node` не найден** («не является командой», «command not found», «is not recognized») → Node не установлен. Дай команду под ОС этой сессии и остановись:
  - Windows: в PowerShell `winget install OpenJS.NodeJS.LTS` или установщик LTS с nodejs.org;
  - macOS: установщик `.pkg` (LTS) с nodejs.org;
  - Linux: Node 22 или новее пакетным менеджером дистрибутива (или NodeSource).
  Последней строкой: «После установки полностью закройте и откройте Claude, иначе он не увидит Node. Потом снова /revizor:setup».
- **JSON получен** → покажи `checks[]` списком: `ok` — ✔, `warn` — ⚠, `fail` — ✖, `info` — ℹ, текст как есть. Есть `install[]` — покажи эти строки. `ok: false` (код 2: нет Node 22, браузера или записи в папку отчётов) → строка «После установки полностью закройте и откройте Claude, потом снова /revizor:setup» и стоп. ✖ только у сети при `ok: true` — окружение в порядке, интернет или VPN не пустили к проверочному адресу: одна строка «Проверьте интернет или VPN; ревью запускать можно» и дальше.
- Запомни из JSON: `out.path` (папка отчётов, обратные слэши замени прямыми), `machine.machine_slow`, `update.newer` (есть новая версия → одна строка «Обновить: /plugin marketplace update revizor, затем /reload-plugins»).

## 2. Библиотека проверки доступности
`doctor` в п. 1 сам скачал её в кэш на этом компьютере со сверкой контрольной суммы (строка «axe-core …»); данные сайтов не отправляются. Отдельной команды не нужно. Строка «axe-core … не скачался» или «нет в кэше» → одна строка человеку: «Скачаю при первом ревью; без неё часть проверок доступности уйдёт в „не проверено“» и дальше.

## 3. Вопросы — по одному
Каждый — отдельный AskUserQuestion. У вариантов короткий `label` и пояснение в `description`.
1. header «Подписка», «Какая у вас подписка Claude? От неё зависит, сколько агентов Ревизор запускает. Агент — отдельный проход модели со своей задачей, каждый тратит лимит подписки»:
   - «Pro» — облегчённый объём, все агенты на Sonnet, по 3 одновременно: бережёт лимит → `pro`;
   - «Max 5×» — стандартный объём → `max5`;
   - «Max 20×» — стандартный или глубокий объём на выбор → `max20`;
   - «API или Team» — оплата за токены (сюда же Enterprise); стандартный или глубокий объём на выбор → `api`.
   Ответ «не знаю» в «Другое» → `pro` и строка «Поставил Pro — самый бережный вариант. Поменять — снова /revizor:setup».
2. Только для `max20` и `api` — header «Объём»: «Какой объём ставить по умолчанию?»:
   - «★ Стандарт» — обычный объём → ничего не добавляй;
   - «Глубоко» — каждая тема отдельным агентом, больше перепроверок, все роли на модели сессии; дольше и больше тратит лимит → `--depth deep --models max`.
   Точные числа агентов и минут Ревизор показывает сметой перед каждым полным прогоном.
3. header «Строгость», «Включить строгий вкус по умолчанию?»:
   - «Нет, обычный» — ошибки, нормы, доступность, факты, закон → `standard`;
   - «Да, строгий» — плюс придирчивость к простыням текста, оговоркам, шаблонному дизайну, шрифтам и палитрам «из коробки»; после отчёта — разбор главного по одному → `strict`.
4. header «Отчёт для», «Кому обычно пойдёт отчёт?»:
   - «Себе» — я владелец, простыми словами → `owner`;
   - «Своей команде» — с техническими деталями → `team`;
   - «Чужой команде» — клиенту: вежливо, без внутренней кухни, без оценок → `external`.

## 4. Файл настроек `~/.revizor/config.json`
Запиши одной командой (значения — из ответов):
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.mjs" --write-config --subscription <pro|max5|max20|api> --profile <standard|strict> --audience <owner|team|external>
```
- Выбрано «Глубоко» (п. 3.2) → добавь `--depth deep --models max`.
- `machine.machine_slow: true` и подписка не `pro` → добавь `--parallel 4`.
- Объём, модели и число агентов одновременно без этих добавок не пиши: их задаёт подписка (Pro → облегчённо, Sonnet, 3 агента). Старые значения этих ключей команда сама уберёт.

Покажи человеку строки «Настройки сохранены: …» из вывода как есть и добавь: «Поменять — снова /revizor:setup или словами в команде (например, „глубоко“)». Код 2 → покажи ошибку одной строкой и переходи к п. 5.

## 5. Правила разрешений (только с явного согласия)
Без правил каждый агент спрашивает разрешение на свои node-скрипты и на запись в папку отчётов — за полный прогон это десятки окон.
1. Покажи, что будет записано, ничего не меняя:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.mjs" --add-rules --dry-run
   ```
   Строки вывода покажи человеку блоком кода как есть и добавь: «Это правила только для скриптов Ревизора этой версии, по одному на скрипт, с точным путём; запись и чтение — только в папке отчётов, чтение — файлов плагина. Любые другие команды и папки по-прежнему спрашивают разрешение». Правил вида `Bash(node:*)`, `Bash(node *)`, `Bash(*)` и путей к скриптам со `*` никогда не предлагай: агенты читают тексты чужих сайтов, а такое правило пропустило бы любой код.
2. AskUserQuestion (header «Разрешения»), «Добавить эти правила в ваши настройки Claude?»: «Добавить» / «Не надо» (буду отвечать на вопросы сам).
3. **«Добавить»:**
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.mjs" --add-rules --yes
   ```
   - «Записано правил: N» или «Все правила уже есть» → одна строка: «Готово. Если вопросы о разрешениях останутся — перезапустите Claude».
   - «не читается как JSON» (код 2) → файл настроек повреждён, скрипт его не тронул. Скажи: «Добавьте правила вручную: /permissions → Allow» и покажи полный список: та же команда с `--dry-run --json`, поле `rules`.
   - «Правил прошлых версий плагина: N» → одна строка: «Старые правила можно удалить в /permissions».
4. **«Не надо»** → строка «Хорошо. Во время ревью отвечайте „разрешать всегда“ на вопросы о node-скриптах Ревизора».

## 6. Пробная проверка на демо-сайте
Демо — вымышленная кофейня с заложенными ошибками; сайт поднимается на этом компьютере и никуда не отправляется.
1. AskUserQuestion (header «Пробный»): «Проверить демо-сайт? Быстрая проверка мобильной версии: замеры и до 3 агентов, это тратит лимит подписки. Ориентир по времени покажу после первого шага, остановить можно в любой момент» — «Проверить демо» / «Пропустить».
2. **«Проверить демо»:**
   - Запусти демо-сервер **в фоне** (`run_in_background: true`):
     ```
     node "${CLAUDE_PLUGIN_ROOT}/scripts/selftest.mjs" --serve-only --serve-sec 3600
     ```
     Прочитай вывод фоновой задачи: адрес демо — строка «Демо: http://127.0.0.1:<порт>/ · iframe: …» (берётся первый адрес) или первая строка вида `http://127.0.0.1:<порт>/`. Нет адреса через минуту или «демо не найдено» → «Демо-сайт не нашёлся; попробуйте на своём сайте: /revizor:quick <адрес> мобильная» и переходи к п. 7.
   - Выполни сценарий из `${CLAUDE_PLUGIN_ROOT}/skills/quick/SKILL.md` для адреса демо: тема `mobile`, флаги `--no-questions --new --out "<папка отчётов>/_demo"` (демо-прогоны лежат отдельно и не путаются с вашими сайтами; внешние сервисы для локального сайта выключены сами). Ориентир времени — из строки прогресса после первого шага, как в quick.
   - После итога quick останови фоновый демо-сервер (инструментом остановки фоновых задач). Забудешь — он сам остановится через час (`--serve-sec 3600`).
   - Пробная проверка прервалась (лимит, ошибка, человек остановил) → строку quick о продолжении не показывай: демо-прогоны лежат в `_demo`, и `--resume` их не найдёт. Вместо неё: «Пробную проверку можно повторить: /revizor:setup». Демо-сервер останови.
   - Строка: «Это пример отчёта на вымышленном сайте. Для своего сайта: /revizor:quick <адрес> <тема> или /revizor:full <адрес>».

## 7. Итог
4–7 строк:
- окружение: готово или что доустановить;
- настройки: путь к `config.json` и папка отчётов (из вывода п. 4), подписка и что она значит по умолчанию;
- правила разрешений добавлены или нет;
- путь к пробному отчёту, если был;
- «Профиль и „кому отчёт“ из /plugin → Configure теперь перекрыты этим файлом: меняйте их через /revizor:setup или словами в команде. Язык отчёта — по-прежнему из /plugin → Configure или словами („по-английски“)»;
- обновления: «/plugin marketplace update revizor, затем /reload-plugins. После обновления снова запустите /revizor:setup: правила разрешений привязаны к папке версии»;
- первые команды:
```
/revizor:quick example.ru мобильная
/revizor:full example.ru
```
