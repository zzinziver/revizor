# Формат находок: `findings/<lens>.json`

Контракт находки проверяет `validate.mjs`. Здесь он словами, с примерами и правилами, которые проверяют `validate.mjs` и `lint-findings.mjs`. После записи файла линза обязана запустить `node "<ROOT>/scripts/validate.mjs" --file "<RUN>/findings/<lens>.json"` и исправить все ошибки.

## 1. Файлы и номера

| Файл | Когда | id находок |
|---|---|---|
| `findings/<lens>.json` | первый круг | `<lens>-01`, `<lens>-02` … (две или три цифры) |
| `findings/<lens>.partN.json` | большой объём частями: `copy.part1.json`, `copy.part2.json` | сквозная нумерация по всем частям |
| `findings/<lens>.r2.json` | второй круг по задачам критика | `<lens>-r2-01` … |
| `verify/<lens>.json` → `added_by_verifier` | находки скептика | `<lens>-v01` … |

Образец id: `^[a-z0-9-]+-(r2-|v)?\d{2,3}$`. Имя линзы — одно из списка: `product, facts, visitor, ux, visual, typography, color, mobile, a11y, copy, seo-tech, seo-content, perf, stability, forms, security, privacy, legal, ecommerce, i18n`. Группа (`group`) пишет отдельный файл на каждую линзу.

## 2. Шапка файла

```json
{
  "lens": "mobile", "agent": "revizor:mobile", "round": 1, "profile": "standard",
  "design_read": "Читаю сайт как: кофейня у метро для жителей района, язык тёплый и простой",
  "skills_used": [],
  "coverage": { "pages": ["home", "p01", "p02"], "viewports": ["390", "1440", "1366x657"],
                "states": ["загрузка", "прокрутка", "бургер"], "checklist_done": 41, "checklist_total": 48, "screenshots_viewed": 22 },
  "not_checked": ["Safari на живом iPhone: нет устройства, см. needs_device_check у mobile-04"],
  "clean_checks": [ { "check": "mobile-12", "result": "поля формы 16 px на всех 4 формах: iOS не увеличит страницу" } ],
  "strengths": [ { "what": "Кнопка «Заказать» в первом экране на 390 px на всех 8 страницах", "why": "помогает дойти до действия: заказ без прокрутки", "where": "all", "number": "8 из 8" } ],
  "for_other_lenses": [ { "lens": "color", "note": "белый текст на фото героя на 390 px, home, 390-fold.jpg: проверить контраст" } ],
  "open_questions": [ { "question": "Таблица меню должна листаться вбок или складываться в карточки?", "why": "обе раскладки допустимы, выбор за владельцем" } ],
  "findings": [ … ]
}
```

- `design_read` — одна строка «Читаю сайт как: <тип> для <аудитории>, язык <настроение>». Подстраивает вкусовые правила под жанр.
- `coverage` — что посмотрено: страницы, ширины, состояния, кадры. Пустая клетка видна критику.
- `not_checked` — что не проверено и почему. Ложное «проверено» хуже честного «не проверено».
- `clean_checks` — пункты чек-листа, которые проверены и в порядке, с цифрой. Скептик может их оспорить.
- `strengths` — не больше 3. Только то, что помогает дойти до действия, с цифрой (`severity.md` §10).
- `for_other_lenses` — замеченное в чужой зоне. Владельцы проверок — `checklists/_owners.md`.
- `open_questions` — то, что решает только владелец.

## 3. Поля находки

| Поле | Обязательно | Что писать |
|---|---|---|
| `id` | да | по образцу §1 |
| `title` | да | утверждение с цифрой или конкретным местом, до 100 знаков (§4) |
| `severity` | да | `P0`–`P3` (`severity.md`) |
| `effort` | да | `S`, `M`, `L` |
| `confidence` | да | `high`, `medium`, `low` (`low` — только с `needs_device_check` или `needs_decision`) |
| `category` | да | короткий код темы на латинице: `overflow`, `contrast`, `cta`, `price-mismatch`, `prompt-injection`… Одинаковые темы — одинаковым кодом: по нему сводятся дубли и вкусовые строки |
| `where` | да | массив мест, хотя бы одно (§5) |
| `sitewide`, `pages_affected_estimate` | нет | одна причина на многих страницах; оценка числа затронутых страниц шаблона по sitemap |
| `evidence` | да | что измерено или видно (§6). Пустое — не находка |
| `method` | да | `script:<имя>`, `probe`, `axe`, `fetch`, `screenshot`, `dom`, `manual`; несколько — через `+` |
| `norm` | да | правило с источником: «WCAG 2.2, 1.4.3: 4,5:1», «Яндекс: title до ~70 знаков». Закон — со статьёй, редакцией и датой сверки по официальному тексту. Для `manual` — правило, на котором держится вывод |
| `scenario` | да | «ширина / действие / состояние → что видит человек или что теряет бизнес». Нет сценария поломки — нет находки |
| `problem` | да | что не так, одним-двумя предложениями |
| `impact` | да | кому мешает и что теряет бизнес |
| `fix` | да | выполнимо на этой платформе: где и что поменять (§7) |
| `before`, `after` | для текста и кода | было → стало: готовый текст или код целиком. У `copy`, `facts`, `seo-content` `before` — текст сайта дословно с той же страницы (код — в `…`), иначе `lint` ставит блокирующую `before_not_found` |
| `fix_place` | желательно | `шаблон`, `общий CSS`, `блок CMS`, `настройки платформы`, `сервер`, `контент`, `внешний сервис` |
| `fix_verified`, `fix_check`; `fix_shot`, `fix_box`, `fix_box_space`, `fix_viewport` | для P0–P1 с CSS/HTML | правка проверена подменой и как именно; кадр «после» `fix_shot` (путь от RUN, обычно `probe/<имя>.jpg`), рамка на нём `fix_box` `[x, y, w, h]` в px картинки (`fix_box_space: "image"`; для кадров `probe/` — так) или в CSS px (`"css"`, по умолчанию), ширина кадра `fix_viewport` (по умолчанию как у `where[0]`). В отчёте — пара «было / стало» |
| `owner` | желательно | `владелец в CMS`, `разработчик`, `копирайтер`, `внешний сервис`, `решение владельца` |
| `needs_decision` | нет | решение за владельцем (развилка, вкус, право) |
| `needs_device_check` | нет | вывод нужно подтвердить на живом устройстве |
| `owner_known` | нет | проблема из `brief.known_issues`, в находке новые цифры |
| `taste` | нет | вкусовое, не выше P3 |
| `q` | нет | номер вопроса владельца из брифа: `"В1"` … или `null` |
| `tags` | нет | строки: `launch` (к запуску беты), `profile:strict`, `platform` … |

На английском прогоне (`--lang en`) `fix_place` и `owner` можно писать английскими значениями: `template, global CSS, CMS block, platform settings, server, content, external service` и `owner in CMS, developer, copywriter, external service, owner decision`.

## 4. Заголовок — утверждение

Заголовок говорит, что не так, где и насколько. В нём есть цифра, цитата в «ёлочках», адрес вида `/menu/` или название места (главная, шапка, форма, кнопка, H1, title…). Без этого `validate.mjs` выдаст ошибку.

| Плохо | Почему | Хорошо |
|---|---|---|
| «Проблемы с контрастом» | нет места и цифры | «Подписи к ценам на /menu/ — серый на белом 2,6:1 при норме 4,5:1» |
| «Мобильная версия требует доработки» | пустая оценка | «На 360 px страница „Меню“ уезжает вбок на 64 px: таблица цен шире экрана» |
| «Возможно, стоит добавить кнопку» | оговорка, нет факта | «На странице „О нас“ нет кнопки заказа: 6 экранов текста заканчиваются подвалом» |
| «Нейрослоп в текстах» | ярлык вместо факта | «В первом экране „не просто кофе, а ритуал“: звучит машинно, оффер не назван» |
| «SEO: title» | нет утверждения | «title главной 112 знаков: в выдаче Яндекса обрежется после 70-го» |

## 5. Место: `where`

```json
{ "pid": "p02", "url": "https://example.ru/menu/", "block": "таблица цен", "selector": ".price-table",
  "viewport": "390", "state": "загрузка", "shot": "snapshot/p02/shots/390.part-02.jpg", "box": [0, 2410, 390, 380], "box_space": "css" }
```

- `pid` — из `pages.json` (`home`, `p01`…). Нет страницы в снимке — `url`.
- `viewport` — `390`, `768`, `1440`, `all`, любое число 200–4000 или окно вида `1366x657`.
- `state` — `загрузка`, `прокрутка`, `бургер`, `попап`, `ошибка формы`, `тёмная тема`, `без JS`, `фокус`, `наведение`… Ошибки при загрузке и при действии — разные состояния.
- `shot` — путь от RUN: `snapshot/<pid>/shots/<файл>` или `probe/<файл>`. Файлы кадров: `390-fold.jpg` (первый экран), `390.part-NN.jpg` (куски), `390-full.jpg` (вся страница, если не слишком длинная), `390.inner-NN.jpg` (прокрутка внутри блока).
- `box` — `[x, y, w, h]` в CSS px документа на этой ширине, от левого верхнего угла страницы. Числа берутся из замера (`page.json`, `measure/*`, `probe`); на глаз рамку не рисуют.
- `box_space: "image"` — если рамку снял с картинки куска; рамка на кадре не из снимка страниц (`probe/…`, кадры из `measure/…`) — всегда `"image"`. Тогда обязательно `shot` этого кадра. `finalize.mjs` пересчитает: `x_css = x / scale`, `y_css = y0 + y / scale` по `shots/index.json` (`y0`, `scale` куска; у первого экрана `scale` равен плотности пикселей, на 390 это 2). Кадры `inner` не пересчитываются: рамка остаётся в пикселях кадра.
- Одна причина на многих страницах — одна находка: `sitewide: true`, в `where` все проверенные места (или 3–5 примеров и `pages_affected_estimate`).

## 6. Доказательство: `evidence`

Две части: сначала факт словами, затем источник одной частью в конце, в квадратных скобках.

«На 390 px таблица цен шире экрана на 34 px: 424 px при окне 390 [measure/mobile.json → overflow 34 px @390, .price-table]»

- Факт — цифры с единицами и нормой: «2,6:1 при норме 4,5:1», «64 px», «LCP 4,8 с по CrUX, 75-й процентиль»; что видно на кадре; чем проверено — простыми словами: «в браузере на компьютере», «эмуляция телефона», «на телефоне». Слово headless — только в скобках: в отчёте для чужой команды оно под запретом.
- Цитата со страницы — в «ёлочках», не длиннее 15 слов, дословно из `text.md` или `raw.html` **той же** `pid`, что в `where`. `lint-findings.mjs` ищет её после выравнивания ё/е, кавычек, тире, неразрывных пробелов и регистра. Цитата с чужой страницы — блокирующая ошибка.
- Для «нет X» — где искал, словами: «в коде, тексте страницы (включая свёрнутые блоки) и 4 кадрах p03 слова „доставка“ нет [raw.html, dom.html, text.md, shots p03]».
- Источник в скобках: файл и поле замера (`[measure/mobile.json → summary.overflow_pages: 3]`), команда `probe` с флагами и итогом (`[probe --pid home --width 390 --tap 352,32 → target_on_top: true]`), кадр. Пути, команды и коды — только в скобках: это техническая часть, чужой команде её не показывают. Линза сдаёт `evidence` чистым; редактор может только сократить или переформулировать его через `rewrite`, без новых цитат и чисел (`finalize.mjs` проверяет).
- Ключи, пароли, токены: «есть, где, тип, сколько знаков», значение не печатать нигде. Персональные данные людей из кода и файлов — маской и числом: «e-mail вида a***@…», «имя в HTML-комментарии», «14 телефонов в открытом файле».

## 7. Правка: `fix`, `before`/`after`, проверка подменой

- Правка выполнима на платформе сайта (`brief.platform`, `platforms/<id>.md`). На конструкторе — через его настройки или блок; «переписать на React» — не правка.
- Готовое значение вместо совета: текст целиком, CSS-правило целиком, «заменить X на Y». «Улучшить контраст» — не правка; «цвет подписи #8a8a8a → #595959 (7,0:1)» — правка.
- `before`/`after` — для текстов и кода. Текст в `after` проходит проверку языка тем же словарём, что и сайт: без оговорок, без выдуманных фактов, без «не X, а Y».
- P0–P1 с правкой CSS или HTML проверяются подменой на живой странице (сайт не меняется):
  - CSS: файл `RUN/probe-js/fix-mobile-03.css` → `probe --pid p02 --width 360 --css "<RUN>/probe-js/fix-mobile-03.css"`;
  - HTML: `--inject-html "<RUN>/probe-js/fix.html" --at "</head>"` или CSS-селектор;
  - ширины: 390 и 1440; правка шапки — ещё бургер на 375 и 834 (открывается касанием, пункты нажимаются); любая CSS-правка — ещё переполнение на 320 и 440;
  - итог в находке: `"fix_verified": true, "fix_check": "probe --css fix-mobile-03.css @320, @360, @390, @440, @1440: overflow 0", "fix_shot": "probe/p02-360-fix.jpg", "fix_box": [0, 240, 720, 760], "fix_box_space": "image", "fix_viewport": "360"` (рамка на кадре `probe/` — в пикселях кадра, как у `box`). С правкой probe делает две загрузки, «до» и «после»; `fix.applied: false` и `fix.blocked_by: "csp"` — правка не применилась (на сайте тоже не заработает), `fix_verified` не ставить.
- Перед «удалить X» — выясни, что X держит (анимация, скрипт, обработчик). Правку, которая ломает узкие ширины или другое состояние, не предлагать.

## 8. Хороший пример

```json
{
  "id": "privacy-02",
  "title": "Форма заказа на /contacts/ уходит методом GET: телефон попадает в адрес страницы",
  "severity": "P0", "effort": "S", "confidence": "high", "category": "pii-in-url",
  "where": [ { "pid": "p04", "url": "https://example.ru/contacts/", "block": "форма «Заказать звонок»", "selector": "form#callback",
               "viewport": "all", "state": "загрузка", "shot": "snapshot/p04/shots/1440.part-02.jpg", "box": [320, 1880, 800, 420], "box_space": "css" } ],
  "sitewide": false, "pages_affected_estimate": null,
  "evidence": "Форма «Заказать звонок» отправляет поля «Имя» и «Телефон» методом GET [measure/forms.json → form#callback method: get; raw.html p04 → method=\"get\"]",
  "method": "script:forms+fetch",
  "norm": "данные с телефоном и именем передаются методом POST: адрес страницы оседает в журналах сервера, истории браузера и отчётах счётчиков",
  "scenario": "1440 и 390 px, отправка формы → телефон виден в адресной строке, в истории браузера и в адресах, которые получают счётчики",
  "problem": "Форма отправляет имя и телефон в строке адреса. Адрес попадает в журналы сервера, историю браузера и в отчёты счётчиков.",
  "impact": "Телефоны клиентов видны третьим сервисам и всем, кто откроет историю браузера на общем компьютере.",
  "fix": "В настройках формы поменять метод на POST: у тега form#callback атрибут method=\"post\". Обработчик заявки принимает POST — проверить одной тестовой заявкой владельца.",
  "before": "<form id=\"callback\" method=\"get\" action=\"/send\">",
  "after": "<form id=\"callback\" method=\"post\" action=\"/send\">",
  "fix_place": "шаблон", "fix_verified": false, "fix_check": null,
  "owner": "разработчик", "needs_decision": false, "needs_device_check": false, "owner_known": false, "taste": false,
  "q": null, "tags": []

```

Почему хорошо: заголовок с местом и следствием; факт словами, источник в скобках; норма техническая и проверяемая; правка выполнима и конкретна; отправку формы Ревизор не делал — проверку обработчика отдал владельцу. Правовую оценку линза без статьи и редакции закона не даёт: в `for_other_lenses` строка для `legal` — «форма p04 передаёт телефон в адресе страницы, оценить по закону о персональных данных».

## 9. Плохие примеры и как исправить

1. **Нет доказательства.** `"evidence": "контраст низкий"` → «Подписи к ценам #9a9a9a на белом 2,6:1 при норме 4,5:1, 14 px [measure/contrast.json → .price small]».
2. **Ложное «проверено».** «Кнопка меню проверена, работает» при `element.click()` → «Бургер на 390 px открывается касанием, сверху сама кнопка [probe --pid home --width 390 --tap 352,32 → target_on_top: true, headless Chromium, кадр probe/home-390-burger.jpg]».
3. **Путь вне скобок.** «measure/mobile.json: overflow 34 px» → «На 390 px страница шире экрана на 34 px [measure/mobile.json → overflow 34 px @390]». Чужой команде скобки не показывают; путь в тексте факта останется в её отчёте.
4. **Пересказ шире источника.** «На всех страницах нет телефона» при 3 проверенных из 20 → «На 3 из 3 проверенных страниц услуг телефона нет в первом экране; страниц этого шаблона по sitemap 14» и `pages_affected_estimate: 14`.
5. **Вкус как дефект.** «Шрифт устарел, P1» → `taste: true`, P3, в `fix` — вариант на выбор владельца.
6. **Невыполнимая правка.** «Переделайте сайт на Next.js» → правка в пределах платформы или `needs_decision` с вариантами.
7. **Оговорка в тексте.** «Возможно, стоит рассмотреть увеличение кнопки» → «Кнопка „Заказать“ 32 × 28 px при норме 44 × 44: увеличить `padding` до 12px 20px». Сомнение — в `confidence`.
8. **Цитата длиннее 15 слов или с другой страницы** → сократить до 15 слов из `text.md` той `pid`, что в `where`.
9. **Одна проблема пятью находками** (по одной на страницу) → одна находка, `sitewide: true`, пять мест в `where`.

## 10. Что проверяют скрипты

`validate.mjs`: JSON разбирается; обязательные поля; значения из списков; `evidence` не пустое; `confidence: low` ⇒ `needs_device_check` или `needs_decision`; `taste: true` ⇒ не выше P3; `fix_verified: true` ⇒ есть `fix_check`; `box` — 4 числа, ширина и высота больше 0; `box_space: image` ⇒ есть `shot`; id по образцу и с префиксом линзы; `title` до 100 знаков с цифрой или местом; `strengths` не больше 3.

`lint-findings.mjs`: `pid` есть в `pages.json` (нет — место без `url` убирается: `pid_unknown`; ни одного известного места — `no_known_place`); кадр `shot` существует внутри RUN; `box` в границах кадра; рамка на кадре не из снимка страниц (`probe/…`) — только `box_space: "image"` (`box_space_needed`); цитаты в «…» дословно на той странице; `before` у `copy`, `facts`, `seo-content` дословно на странице (`before_not_found`); стоп-слова тона из `tone.md` в `title`, `problem`, `impact`, `fix`, `after` и в факте `evidence` (без части в [скобках]; цитаты и код не считаются).

Ошибка `validate` — исправить до сдачи. Блокирующие ошибки `lint` — `quote_not_found`, `quote_other_page`, `before_not_found`, `no_known_place`, `schema_fatal`: находка не идёт в отчёт, пока скептик не подтвердит её замером. Ремонтируемые (`shot_missing`, `shot_outside_run`, `box_not_in_shot`, `box_out_of_bounds`, `pid_unknown`) `merge.mjs` чинит сам: убирает битую ссылку, находка остаётся.

Правки редактора проверяет `finalize.mjs`:
- Слияние: текст, вердикт, `confidence` и флаги находка берёт у одного члена — с наибольшей важностью; важность — наибольшая из слитых.
- `drop` с id оставшейся находки в `why` становится слиянием, только если находки связаны: один кластер дублей, один элемент, рамки на одной странице и ширине пересекаются (IoU ≥ 0,5), одна страница и одна категория, одна категория и похожие заголовки. Нет связи — отказ «не дубль».
- P0–P1 без вердикта скептика снять нельзя: её снимает только вердикт `rejected` («нужна перепроверка скептиком»).
- Новые числа и цитаты в `title`, `problem`, `impact`, `scenario`, `evidence` через `rewrite` — отказ.
- Итоговая сверка: `mixed_text` — у слитой находки текст одного члена, а вердикт или флаги другого; `external_unverifiable_text` — для чужой команды показан текст члена, которого отчёт сам не показал бы. Любое из них — `finalize.mjs` выходит с кодом 1 («проверка не прошла»); отказы отдельных правок — код 4.
