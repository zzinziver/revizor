# Платформа: Next.js, Nuxt и сайты-приложения (SPA)

**Для:** `brief.platform.name` = `Next.js`, `Nuxt`, `React SPA`, `Vue SPA`, `Angular`, `Gatsby` и другие фреймворки на JS (`pages.json → stack.cms`).
**Кто читает:** все линзы; больше всего — `seo-tech`, `stability`, `perf`, `security`, `a11y`, `forms`.
**Сверено:** 24.10.2026. Код и сервер у владельца в руках: скидки «платформа» нет, почти всё — работа разработчика (`owner: "разработчик"`).

## 1. Как узнать и как устроено

- Next.js: `__NEXT_DATA__` или `#__next` (Pages Router), `self.__next_f` и `/_next/static/` (App Router), заголовок `x-powered-by: Next.js`; хостинг Vercel — `x-vercel-id`.
- Nuxt: `__NUXT__`, `__NUXT_DATA__`, `/_nuxt/`. Vue: `data-v-app`. Angular: `ng-version`.
- React или Vue без серверной отрисовки: в исходном HTML пустой `<div id="root">` или `#app`, весь текст приходит скриптом (`crawl.mjs` пишет сигнал «пустой #root»).
- Три режима отдачи: страница собирается на сервере (SSR), заранее (SSG/ISR) или только в браузере (CSR). От режима зависит, что видят поисковики, ИИ-боты и превью в мессенджерах.

## 2. Типовые проблемы по линзам

| Линза | Что проверить | Где в замерах | Важность |
|---|---|---|---|
| `seo-tech` | Отрисовка только в браузере: в исходном HTML нет H1, текста, ссылок, canonical | `seo.json → items[].text.js_only`, `h1.raw_count`, `canonical.differs_raw_dom`, `jsonld.only_in_js` | P1 для сайта, которому нужен поиск (Google и Яндекс JS исполняют, но с задержкой и без гарантии, ИИ-боты — обычно нет); P0 — только с доказательством выпадения из индекса (Вебмастер или Search Console владельца); P2 — если пусто только на части шаблонов |
| `seo-tech` | title и meta robots меняет только скрипт; noindex появляется только после JS | `items[].title.changed_by_js`, `robots.noindex_only_in_js` | P1 |
| `seo-tech` | Несуществующий адрес отдаёт 200 и пустую страницу или главную (soft-404) | `site.soft404[].verdict`, `says_not_found` | P1 |
| `seo-tech` | Превью в мессенджерах пустое: OG-теги ставит скрипт | `items[].og.in_raw`, `site.bots` | P1 |
| `stability` | Ошибки гидратации в консоли («Hydration failed», расхождение текста сервера и браузера), мигание контента | `page.json → console`, `exceptions` | P1 на главной и страницах услуг |
| `stability` | Якоря на страницах с переключаемым контентом промахиваются до гидратации | `mobile.json` (навигация по якорям) | P2 |
| `stability` | Устаревшие данные из кэша ISR или CDN: цена на одной странице старая | заголовки `age`, `x-nextjs-cache`, `x-vercel-cache`, `cache-control` документа — `snapshot/<pid>/page.json → raw.headers`; `headers.json → items[].html_cache` — только Cache-Control; сверка цен `facts` | P1 при расхождении цены |
| `security` | `__NEXT_DATA__` и данные страницы раздуты служебными полями: внутренние адреса API, почты, ключи | ключи — `headers.json → secrets[]` (`public: true` — публичный ключ, не находка), `secrets_scan` (`files: 0` — `not_checked`); адреса API и почты — `raw.html` (`__NEXT_DATA__`) | P0 при ключе или ПДн; иначе P3 (вес — `perf`) |
| `security` | Версия Next.js из уязвимого диапазона. Примеры на дату сверки: обход middleware CVE-2025-29927 (любой роутер; исправлено в 15.2.3, 14.2.25, 13.5.9, 12.3.5); уязвимости React Server Components — только **App Router** (признак `self.__next_f`; Pages Router с `__NEXT_DATA__` не затронут): RCE CVE-2025-55182 (в Next.js — CVE-2025-66478), затем DoS CVE-2025-55184 с полным исправлением CVE-2025-67779 и раскрытие кода CVE-2025-55183. Для этих CVE исправлено в версиях из [бюллетеня от 11.12.2025](https://nextjs.org/blog/security-update-2025-12-11): 14.2.35, 15.0.7, 15.1.11, 15.2.8, 15.3.8, 15.4.10, 15.5.9, 16.0.10; ранние «исправленные» версии начала декабря 2025 от DoS не защищают. Безопасными их не называй: 14.10.2026 опубликовано [GHSA-2464-fhr4-w9xw](https://github.com/advisories/GHSA-2464-fhr4-w9xw) — выполнение кода через Image Optimization при SVG, любой роутер, версии 10.0.0–15.5.27 и 16.0.0–16.4.0, исправлено в 15.5.28 и 16.4.1 | `headers.json → libraries` (список уязвимостей скрипта знает не все CVE — сверь версию с [блогом Next.js](https://nextjs.org/blog) на дату прогона); только сопоставление точной версии, без эксплуатации | совпадение точной версии — P1, `needs_decision`, `confidence` по точности версии; P0 — только доказанная уязвимость (`severity.md`), сопоставлением версии она не доказывается; версия неизвестна — `open_questions` |
| `security` | Карты исходников в проде (`productionBrowserSourceMaps`) | `headers.json → sourcemaps` | P2 |
| `security` | Заголовок `x-powered-by: Next.js` раскрывает стек | `headers.json → home.disclosure` | P3 |
| `perf` | Большой JS-бандл, гидратация всей страницы, длинные задачи | `perf.json` (TBT, вес JS) | P1 при TBT на 390 > 600 мс |
| `perf` | Картинка первого экрана грузится лениво (у `next/image` нет `priority`) | `perf.json` (LCP-элемент), `raw.html` (`loading="lazy"` у героя) | P1 |
| `a11y` | При переходе между страницами без перезагрузки фокус и объявление новой страницы не меняются; скринридер не узнаёт о переходе | `a11y.json` (клавиатура), AX-дерево | P2 |
| `forms` | Счётчики считают переход по маршруту дважды или не считают вовсе | `forms.json` (дубли, двойная инициализация) | P2 |
| `ux` | «Назад» не возвращает к прокрутке и фильтрам, перезагружает страницу | ручная проверка `probe`, `human-checks.md` | P2 |

## 3. Что исправимо и где

| Задача | Где править | `fix_place` | `owner` |
|---|---|---|---|
| Текст и ссылки в исходном HTML | серверная отрисовка или сборка заранее для публичных страниц: Next.js — серверные компоненты или статическая генерация; Nuxt — `ssr: true` или генерация; чистый SPA — пререндер публичных страниц или переезд на фреймворк с SSR (L, `needs_decision`) | шаблон | разработчик |
| title, description, canonical, OG | Next.js App Router — `metadata` / `generateMetadata`; Pages Router — `next/head`; Nuxt — `useHead` / `useSeoMeta` | шаблон | разработчик |
| 404 со статусом 404 | Next.js — `notFound()` и `not-found`; Nuxt — `createError({ statusCode: 404 })`; на статическом хостинге — правило для неизвестных путей | шаблон | разработчик |
| `robots.txt`, `sitemap.xml` | Next.js — `app/robots.ts`, `app/sitemap.ts` или файлы в `public/` | шаблон | разработчик |
| Заголовки безопасности, редиректы, слэш | `next.config` (`headers()`, `redirects()`, `trailingSlash`), middleware или настройки хостинга | сервер | разработчик |
| Скрыть `x-powered-by` | `poweredByHeader: false` | сервер | разработчик |
| Обновление уязвимой версии | обновить Next.js и React до последнего патча своей ветки по бюллетеням [nextjs.org/blog](https://nextjs.org/blog) на дату прогона (не до версии из старого бюллетеня), пересобрать и выложить | шаблон | разработчик |
| Картинка первого экрана | `priority` у `next/image` (или `fetchpriority="high"`), без `loading="lazy"` | шаблон | разработчик |
| Фокус при смене маршрута | перенос фокуса на H1 новой страницы и объявление через `aria-live` | шаблон | разработчик |

## 4. Ограничения

Ограничений платформы нет: всё правится в коде. Исключение — хостинг без доступа к заголовкам (статический хостинг с бедными настройками): тогда P3 и вариант «перенести на хостинг с настройкой заголовков» как решение владельца.

## 5. Ложные срабатывания и артефакты съёмки

- Контент пустой в снимке, а в живом браузере есть: проверь `page.blocked` — контент мог грузиться POST-запросом, который страховка оборвала. Это артефакт съёмки: строкой в `not_checked` и предложение повторить с `--allow-load-posts` (решает оркестратор).
- `self.__next_f` и большие встроенные JSON — устройство App Router, не утечка, пока внутри нет секретов и ПДн.
- `/_next/image?url=…` — служебный адрес оптимизатора картинок, не параметрический дубль страницы.
- Заголовок `x-vercel-cache: MISS` при первом заходе — норма.
