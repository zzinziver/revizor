# Платформа: WordPress (и WooCommerce)

**Для:** `brief.platform.name = "WordPress"` (`pages.json → stack.cms`).
**Кто читает:** все линзы; больше всего — `security`, `seo-tech`, `perf`, `copy`, `forms`, `ecommerce`.
**Сверено:** 24.10.2026. Почти всё правится: шаблон (тема), плагины, сервер. Поэтому скидки «платформа» здесь почти нет: важность — по влиянию.

## 1. Как узнать

- Пути `/wp-content/`, `/wp-includes/`, `/wp-json/`; `<meta name="generator" content="WordPress X.Y">`; заголовок `Link: <…/wp-json/>`; объект `window.wp`.
- Тема — по пути `/wp-content/themes/<имя>/`; плагины — по путям `/wp-content/plugins/<имя>/`. Версии видны в `?ver=` у файлов (подсказка, не доказательство).
- Конструкторы страниц: Elementor, WPBakery, Divi и подобные — по классам и путям. Магазин — WooCommerce (`woocommerce` в классах и путях).

## 2. Типовые проблемы по линзам

| Линза | Что проверить | Где в замерах | Важность |
|---|---|---|---|
| `security` | Версия ядра раскрыта (`generator`, `readme.html`) и отстаёт от актуальной ветки | `headers.json → items[].generator`, `cms.wordpress`; `--probe`: `readme.html` | P2; P1 при известной уязвимости версии (уверенность ≥ 8/10) |
| `security` | Перечисление пользователей через `/wp-json/wp/v2/users` (логины видны) | `headers.json → probe` (только при `--probe` на своём сайте) | P2 |
| `security` | `xmlrpc.php` отвечает (подбор паролей, усиление DDoS) | `headers.json → probe` | P2 |
| `security` | Листинг `/wp-content/uploads/` открыт | `headers.json → probe` | P2; P1, если там документы с ПДн |
| `security` | Старые jQuery и jquery-migrate из темы | `headers.json → libraries` | по версии (`summary.vulnerable_libraries`) |
| `seo-tech` | Включён «Попросить поисковые системы не индексировать сайт» после запуска: noindex на всех страницах | `seo.json → items[].robots.noindex`, `pages.json → beta_signals` | P0 на живом сайте |
| `seo-tech` | Мусор в индексе: архивы меток, авторов, дат, страницы вложений, `?p=`, `?replytocom=`, страницы поиска `?s=` | `pages.json → by_template`, sitemap; `seo.json → items[].links.param_links` (`?p=` скрипт относит к `pagination`, `?s=` — к `filter`, `?replytocom=` — к `other`; `samples`), запасной путь — адреса с `?` в `measure/links.json → items[]` (`internal: true`); `site.url_variants` и `items[].links.tracking_params` эти адреса не проверяют | P2 |
| `seo-tech` | Две карты сайта: встроенная ядра (`wp-sitemap.xml`) и от SEO-плагина; в одной служебные адреса | `site.sitemap` | P2 |
| `seo-tech` | Пагинация `/page/2/` с canonical на первую страницу | `items[].canonical.self` | P2 |
| `seo-tech` | Смешанный контент после переезда на https: старые `http://` в текстах записей | `headers.json → items[].mixed_content` | P2 |
| `perf` | Конструктор страниц: тяжёлый DOM, CSS и JS всех виджетов на каждой странице | `mobile.json → summary.heavy_dom`, `perf.json` | P2 |
| `perf` | Нет кэша страниц: высокий TTFB на каждой загрузке | `perf.json` (TTFB сериями) | P1 при TTFB > 1,5 с |
| `perf` | Картинки без WebP/AVIF и без `srcset` нужного размера | `perf.json` (топ-ресурсы) | P2 |
| `stability` | Предупреждения PHP в HTML, страница ошибки со стектрейсом | `headers.json → error_page.traces`, `raw.html` | P1 (раскрытие путей — `security`) |
| `copy` | Непереведённые строки темы и плагинов: «Read more», «Add to cart», «Search…», «No products found», «Previous / Next», даты «October 24», «1,500.00», «RUB» вместо «₽» | `textscan.json` (непереведённое) | P2 |
| `privacy`, `legal` | Contact Form 7, WPForms и подобные: где хранятся заявки (база сайта, почта, внешний сервис) и reCAPTCHA (сервис Google — трансграничная передача для РФ) — `privacy`; согласие отдельной галочкой — `legal` | `forms.json`, `privacy.json → summary.cross_border` | по `markets/*`; `forms` передаёт через `for_other_lenses` |
| `a11y` | Тема убирает обводку фокуса, нет ссылки «к содержанию» | `a11y.json → items[].check` | P1–P2 |
| `ecommerce` | WooCommerce: `/cart/`, `/checkout/`, `/my-account/` под noindex; фильтры `?filter_…`, `?orderby=` не плодят индексируемые дубли; разметка Product из плагина совпадает с ценой на странице | `seo.json → items[].robots`, `items[].links.param_links` (`filter`, `sort` — `orderby`, `samples`), запасной путь — адреса с `?` в `measure/links.json → items[]`, `items[].jsonld.mismatches` | P1 при расхождении цены |

## 3. Что исправимо и где

| Задача | Где править | `fix_place` | `owner` |
|---|---|---|---|
| title, description, canonical, noindex архивов, карта сайта | SEO-плагин (настройки типов записей и таксономий) или тема | настройки платформы | владелец в CMS |
| Запрет индексации сайта | «Настройки → Чтение», галочка про поисковые системы | настройки платформы | владелец в CMS |
| 301-редиректы | плагин редиректов или конфиг сервера | сервер | разработчик |
| Заголовки безопасности, сжатие, кэш статики | конфиг сервера (nginx/Apache) или плагин безопасности | сервер | разработчик |
| `xmlrpc.php`, `/wp-json/wp/v2/users` | закрыть на сервере или плагином безопасности (проверить, не нужен ли `xmlrpc` мобильному приложению или интеграции) | сервер | разработчик |
| CSS-правка | «Внешний вид → Настроить → Дополнительные стили» или дочерняя тема | общий CSS | разработчик |
| JSON-LD | SEO-плагин или дочерняя тема | шаблон | разработчик |
| Скорость | плагин кэша страниц или кэш на сервере, оптимизация картинок, отключение лишних плагинов на страницах | сервер | разработчик |
| Перевод строк темы | файлы перевода темы или плагин перевода | шаблон | разработчик |
| Обновления ядра, темы, плагинов | админка, с резервной копией | внешний сервис | разработчик |

## 4. Ограничения

- Своих ограничений почти нет. На простом хостинге без доступа к конфигу сервера заголовки и сжатие настраиваются плагином или в панели хостинга — так и писать в `fix`.
- Конструкторы страниц дают тяжёлую разметку; переезд с конструктора — L, `needs_decision`.

## 5. Ложные срабатывания

- `/wp-json/` и `/wp-login.php` существуют на любом WordPress — сами по себе не находка.
- `?ver=` у CSS и JS ставит ядро для сброса кэша файлов — к индексации страниц отношения не имеет.
- Версия плагина из `?ver=` бывает версией темы или ядра — не доказательство уязвимости.
- Страницы вложений в новых установках ядро отключает по умолчанию (с версии 6.4 — сверить в справке WordPress). Находка только по факту: адрес вложения отвечает 200 и есть в sitemap.
