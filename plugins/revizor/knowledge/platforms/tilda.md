# Платформа: Тильда (Tilda)

**Для:** `brief.platform.name = "Tilda"` (`pages.json → stack.cms`).
**Кто читает:** все линзы; больше всего — `seo-tech`, `perf`, `mobile`, `stability`, `forms`, `a11y`, `security`.
**Сверено:** 24.10.2026. Интерфейс платформы меняется. Пункт с пометкой «сверить в справке» в `fix` пишется двумя путями: «если в настройках есть X — там; иначе — Y».

## 1. Как узнать

- В коде: `tildacdn.com`, `data-tilda-page-id`, `#allrecords`, `.t-records`, `tildastat`; заголовок `x-tilda-server`; технический домен `*.tilda.ws` (`pages.json → beta_signals: preview_domain`).
- Блоки двух видов: стандартные (номера вида T123, T396 и т. п.) и Zero Block (элементы с абсолютным позиционированием на артбордах по брейкпоинтам).
- Стандартные блоки перестраиваются на типовых ширинах платформы, меню уходит в бургер на одной из них; брейкпоинты Zero (по умолчанию 1200, 960, 640, 480, 320 px) автор меняет сам. В находке — только ширины, которые видны в кадрах и `mobile.json` этого сайта.
- Магазин Tilda Store: блоки каталога и корзины (в коде `t-store`, `js-store`, корзина `t706`; страницы товаров вида `/tproduct/<id>-…`; признаки по опыту сборки — сверить в коде страницы). `crawl.mjs` пишет `pages.json → stack.store: "Tilda Store"`; метки нет, а признаки в коде есть — это тоже магазин. В обоих случаях читай ещё `verticals/shop.md` и раздел «Магазин Tilda Store» ниже.

## 2. Типовые проблемы по линзам

| Линза | Что проверить | Где в замерах | Важность |
|---|---|---|---|
| `seo-tech` | Заголовки в Zero Block отдаются `div`, пока автор не выставил тег вручную: H1 нет в исходном HTML | `seo.json → items[].h1.raw_count`, `items[].headings.*` | нет H1 на посадочной — P1 |
| `seo-tech` | Порядок элементов в HTML = порядок их создания в Zero, z-index его не меняет: H3 карточек стоит раньше H2 секции | `items[].headings.h3_before_h2`, `headings.skips` | P2 |
| `seo-tech` | Кнопки и плашки размечены как H2–H4 | `items[].headings.cta_like` | P3 |
| `seo-tech` | Адреса-двойники платформы: страница открывается и по `/page<id>.html` (`<id>` — `data-tilda-page-id` в `raw.html`); нужен canonical на чистый адрес | `seo.json → site.url_variants[]` с `kind: "platform_alias"` (`status`, `final_url`, `canonical_to_original`, `kind_of_answer`, `duplicate`; при дубле флаг `duplicate-platform_alias`). Скрипт строит вариант по атрибуту `data-tilda-page-id` для первых 2 страниц с ответом 200. Варианта нет (нет `page_ids` или замер обрезан по времени) — проверь сам: `node "<ROOT>/scripts/probe.mjs" --run "<RUN>" --url <сайт>/page<id>.html --no-shot --expr "document.querySelector('link[rel=canonical]')?.href"` → `status`, `final_url`, `result`. Не проверил — `not_checked`, не «чисто» | 200 и canonical не на чистый адрес — P2 |
| `seo-tech` | Своя страница 404 задана в настройках? Иначе случайный адрес даёт платформенную заглушку | `site.soft404[].verdict`, `own_template` | P2 |
| `seo-tech` | Головной код сайта (HTML в head) наследуется всеми страницами: одна разметка BreadcrumbList или FAQPage на всех | `items[].jsonld.mismatches`, `jsonld.types` | P2 |
| `seo-tech`, `mobile` | Мобильные дубли текста лежат за артбордом (x ≈ −1000 px): посетитель их не видит, поисковик видит текст дважды | `page.json → parity`, `text.md` (дубли абзацев), `dom.html` | P3 |
| `perf` | Страница скрыта до загрузки скриптов (`.t-records{opacity:0}`): первый показ ждёт JS | `perf.json` (FCP, LCP), кадр fold | P2; по замеру с блокировкой основного скрипта |
| `perf` | Ленивая загрузка подставляет картинку первого экрана поздно: файл скачан, LCP наступает на секунды позже | `perf.json` (LCP-элемент, время скачивания файла) | P1, если LCP на 390 > 4 с |
| `perf` | Появление блоков при прокрутке на первом экране: LCP позже примерно на 0,5 с | `mobile.json → code.motion`, `perf.json` | P2 |
| `perf` | У картинок Zero нет `width`/`height` | `layout.json`, CLS в `perf.json` | P2 при CLS > 0,1 |
| `perf` | Google Fonts без `font-display` | `fonts.json`, `perf.json` | P2 |
| `mobile` | Автомасштаб Zero (CSS `zoom`) на окнах ноутбуков: размеры по `getBoundingClientRect` и `offsetWidth` расходятся | `mobile.json → summary.rescale_laptop` | по виду кадра |
| `forms` | Обязательность задана только правилом платформы (`data-tilda-req`), атрибута `required` нет | `forms.json → items[].check: required-not-programmatic` | P2 |
| `forms` | Маска телефона выбирает страну по IP: посетителю из другой страны или через VPN подставляется чужой код; у части стран не снимается ведущий 0; список стран может быть не на языке сайта и уходить за экран, если поле внизу | только чтение кода и кадр; ввод в поле телефона — нет | `needs_device_check`, P2 |
| `forms` | Кнопка калькулятора с `type=submit` и подключёнными приёмщиками заявок: при ошибке JS она отправит пустую заявку | `forms.json`, `page.json → exceptions` | P1 при ошибке JS |

| `stability` | После правки шапки или подвала их надо переопубликовать на всех страницах: старые страницы показывают старую версию | сравнить шапку на нескольких `pid` | P2 |
| `a11y` | Попапы платформы: фокус не уходит в попап, нет возврата фокуса, Tab уходит под попап | `a11y.json → items[].check` | P1 у формы заявки |
| `copy` | Остатки шаблонных текстов блоков: «Заголовок блока», «Описание», «Lorem ipsum», шаблонные картинки | `textscan.json` | P0 на виду |
| `seo-content` | Превью ссылки: мессенджеры не всегда забирают `og:image` с CDN-доменов платформы — проверить превью вживую, своя картинка 1200×630 с домена сайта надёжнее | `site.og_images[].host` | `needs_device_check` |
| `security` | Заголовки безопасности (HSTS, CSP и др.) владельцу недоступны | `headers.json → home.*` | P3 «платформа» |

**Магазин Tilda Store** (при признаках из §1; вместе с `verticals/shop.md`):
- `seo-tech`: у товара своя страница с текстом в исходном HTML или только всплывающая карточка поверх каталога; страницы товаров в sitemap; разметка Product с ценой и наличием (`items[].jsonld.*`). Только всплывающие карточки — у товаров нет адресов для поиска: P2 для магазина, которому нужен поиск.
- `facts`, `ecommerce`: цена в каталоге = в карточке = в корзине (по видимому тексту и разметке, без покупки); фид для Яндекса и Google из настроек магазина — выборка «фид против витрины».
- `forms`, `legal`: корзина собирает имя и телефон — согласие и политика по `markets/*`; оплата — на стороне платёжного сервиса, Ревизор её не проходит.

## 3. Что исправимо и где

| Задача | Где править | `fix_place` | `owner` |
|---|---|---|---|
| Тег H1/H2 у заголовка в Zero | редактор Zero → элемент → настройка тега | блок CMS | владелец в CMS |
| title, description, OG-картинка | настройки страницы (разделы SEO и соцсетей) | настройки платформы | владелец в CMS |
| Запрет индексации страницы | настройки страницы → запрет индексации | настройки платформы | владелец в CMS |
| Своя страница 404 | настройки сайта (сверить в справке) | настройки платформы | владелец в CMS |
| 301-редиректы | настройки сайта, раздел редиректов (сверить в справке; если нет — оставить старые адреса живыми с canonical на новый) | настройки платформы | владелец в CMS |
| JSON-LD, мета-теги, свои стили для всего сайта | HTML-код для вставки в head сайта (наследуется всеми страницами — разметку конкретной страницы класть в блок этой страницы) | шаблон | разработчик |
| CSS-правка одного места | HTML-блок на странице со `<style>`; кастом внутри Zero держать с `!important`: пересохранение Zero переписывает CSS элементов | блок CMS | разработчик |
| Картинка первого экрана без ленивой загрузки | настройки ленивой загрузки (сайт или блок) или своя картинка в коде с `fetchpriority="high"` | настройки платформы | владелец в CMS |
| Шрифты | свои шрифты в настройках сайта или подключение через head с `font-display: swap` | настройки платформы | разработчик |
| Шапка и подвал | правка в общем блоке → переопубликовать все страницы | блок CMS | владелец в CMS |

## 4. Ограничения платформы (P3 с пометкой «платформа», `fix_place: "настройки платформы"`)

- `robots.txt` не редактируется (справка платформы: правка только через экспорт сайта на свой хостинг). Clean-param не добавить — не требовать.
- Заголовки ответа сервера (HSTS, CSP, кэш, сжатие) не настраиваются.
- Набор скриптов и встроенного CSS платформы на каждой странице; потолок мобильной оценки PageSpeed задаёт платформа. Находка — только наше сверх этого (тяжёлые картинки, видео, свои скрипты), с цифрой из `perf.json`.
- Служебные страницы шапки и подвала закрыты в `Disallow` — это норма.
- Лимит размера HTML-блока: длинный код не помещается; выход — несколько блоков или код в head.
Есть обходной путь (свой код в head, другой блок) — важность по влиянию, в `fix` — этот путь.

## 5. Ложные срабатывания

- Элементы за левым краем артборда — скрытые дубли для других ширин, не переполнение (`mobile.json` переполнение считает с учётом обрезки предком).
- Оборванные служебные запросы статистики платформы (POST) — работа страховки Ревизора, не ошибка сайта.
- Скрипт платформы перехватывает вставку в поле телефона и вставляет сам — не «запрет вставки».
- Низкая SEO-оценка Lighthouse на страницах с noindex — ожидаемо.
- Служебная страница без noindex, но под `Disallow` — не проблема.
