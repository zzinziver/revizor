# Процедура `group` — несколько линз одним агентом

Процедура для `revizor:group`. Группа выполняет линзы из строки `LENSES=` по очереди так, как их выполнили бы отдельные агенты, и пишет по файлу на линзу. Отчёт и реестр от пресета не зависят: `merge.mjs`, скептики, критик и редактор видят обычные `findings/<lens>.json`.

Выгода группы — общее чтение: ядро, бриф, `pages.json`, общие замеры и общие кадры читаются один раз. Риск группы — последняя линза списка получает меньше внимания, когда кончается контекст. Поэтому линзы сдаются по одной, контекст и кадры делятся по бюджету (§4, §7).

Пути — от RUN. Формат файлов — `findings-format.md`, владельцы пересекающихся проверок — `_owners.md`, важность — `severity.md`. «Главная» — `home`; при строке `PAGES=` в промте — первая pid из неё.

## 1. Промт и состав

- **[group-01]** Строки промта: `ROOT=`, `RUN=`, `ROUND=`, `LENSES=a,b,c`, строка `PROFILE=… · AUDIENCE=… · MARKET=… · VERTICAL=… · DEPTH=… · LANG=…`; иногда `PAGES=`, `MANUAL_SHOTS=`, `TASK=fix` (их смысл — `agents/group.md` §0). После `LENSES` может стоять пометка в скобках, например «(ux — только сценарии форм)»: она сужает зону этой линзы (group-22).
- **[group-02]** Состав группы задаёт `state.mjs` по пресету глубины (lite, standard) или теме быстрой проверки. Линзы не добавляешь и не выкидываешь. Линза без файла агента и без чек-листа — group-27.
- **[group-03]** Какие группы бывают и что у них общего:

| Где | `LENSES` | Общие входы (читать один раз) | Общие кадры |
|---|---|---|---|
| lite | `product, facts, ux, forms` (+`ecommerce` у магазина) | `text.md` главной и продуктовых страниц, `pages.json → nav_lists`, `measure/forms.json`, `measure/links-blocks.json`, `measure/mobile.json` (`nav`, `summary.no_cta_390`, `fold_no_cta_390`) | первые экраны 390 и 1440 главной и продуктовых страниц, кадры попапов `measure/forms/*.jpg` |
| lite | `visual, typography, color, mobile` | `measure/layout.json`, `fonts.json`, `contrast.json`, `vision.json`, `mobile.json` | первые экраны и куски 390 и 1440 всех шаблонов, листы `measure/vision/*.jpg`, `measure/mobile/*.jpg` |
| lite | `a11y, perf, stability` | `measure/a11y.json`, `axe.json`, `perf.json`; `snapshot/errors.json` (ошибки JS, консоль, сеть по страницам) | первые экраны 390, листы `measure/perf/<pid>-film.jpg`, кадры своих проб |
| lite | `copy, seo-tech, seo-content` (+`i18n` при нескольких языках) | `text.md` всех страниц, `measure/textscan.json`, `seo.json`, `links.json`; `page.json` (Grep: `title`, `description`, `h1`, `og`) | первые экраны 390 и 1440 главной и 2–3 продуктовых страниц |
| lite, standard | `security, privacy, legal` | `measure/headers.json`, `domain.json`, `privacy.json`, `forms.json` (согласия, обработчики), `text.md` политики и подвала | первые экраны 390 и 1440 главной (cookie-баннер), страница с формой |
| standard | `ux, forms` | `pages.json → nav_lists`, `measure/mobile.json` (`nav`, `burger`), `forms.json`, `links-blocks.json` | первые экраны внутренних страниц на 1440, бургер на 390, попапы форм |
| standard | `visual, typography, color` | `measure/layout.json`, `fonts.json`, `contrast.json`, `vision.json` | первые экраны и куски 390 и 1440 всех шаблонов |
| standard, quick «seo» | `seo-tech, seo-content` | `measure/seo.json`, `links.json`, `textscan.json`, `text.md` | первые экраны главной и посадочных |
| standard | `perf, stability` | `measure/perf.json`, `headers.json`; `snapshot/errors.json`; `page.json` (Grep: `scripts`, `network`) | листы `measure/perf/<pid>-film.jpg`, первые экраны 390, кадры проб |
| quick «forms» | `forms, ux` с пометкой «ux — только сценарии форм» | `measure/forms.json`, `mobile.json → burger` | попапы форм, бургер |

Флаги `--lenses` и `--skip` могут сократить группу. Группу из одной линзы оркестратор запускает агентом этой линзы, без `group`.

## 2. Что уже сдано (продолжение)

Оркестратор перезапускает группу, пока у какой-то её линзы нет файла находок. Поэтому новый запуск начинает с проверки.

- **[group-04]** По каждой линзе из `LENSES`: `node "<ROOT>/scripts/state.mjs" --run "<RUN>" --get lens:<lens>` (второй круг — `r2:<lens>`) и есть ли `findings/<lens>.json` (`.r2.json`). Отметка `ok` или `skipped` и файл есть — линза сдана: не переделываешь, в ответе строка «сдана раньше».
- **[group-05]** Файл есть, отметки `ok` нет (прошлый запуск оборвался после записи) — `validate.mjs --file` на этот файл. Код 0 — допиши `notes/<lens>.md`, если его нет, и поставь `lens:<lens>=ok`. Ошибки — исправь файл, потом отметка.
- **[group-06]** Отметка `partial` и файл есть — дополняешь разделы из `not_checked` этой линзы, проверенное заново не проходишь; при полной сдаче отметка `ok`.

## 3. Порядок

- **[group-07]** Общее чтение один раз: `core.md`, этот файл, строки `_owners.md` по линзам группы (Grep), `brief.json` (нет — `brief.input.json` и `pages.json`), `pages.json`. Справочники, которые требуют файлы линз (профиль, рынок, вертикаль, платформа, языковые), — один раз на группу и только нужные разделы (Grep, Read с `offset`/`limit`).
- **[group-08]** Для каждой линзы — `agents/<lens>.md` и `checklists/<lens>.md` целиком. Нормы у соседних линз разные, чужую норму в линзу не переносишь: цели касания у `a11y` и у `mobile` — обе нормы, 24 × 24 px (WCAG 2.2, 2.5.8, AA) и 44 × 44 px (Apple, 2.5.5, AAA), а важность провала у каждой своя по её чек-листу; подпись источника цифр — у `perf`; уверенность от 8 из 10 — у `security`.
- **[group-09]** План кадров (§4) и доля контекста на линзу (group-28) — до первого Read кадра.
- **[group-10]** Линзы — по очереди в порядке `LENSES`. На каждой — шаги «Порядок работы» её файла агента: её чек-лист, её замеры, её пробы, её строгость.
- **[group-11]** Большие замеры — частями. Файл больше 100 КБ целиком не читаешь: (1) сводка скрипта `<RUN>/stdout/<скрипт>.md`; (2) Read с `limit: 80` — шапка, `partial`, `summary`, `flags`, `not_checked`; (3) Grep по ключу и pid с контекстом — например `"pid": "p03"` -A 60, `"exceptions": \[` -A 6, `"status": [45]\d\d` -B 2; (4) Read с `offset`/`limit` найденных строк. Ошибки страниц — `snapshot/errors.json` вместо всех `page.json`. Замер, нужный нескольким линзам, читаешь один раз и держишь короткой выпиской: «страница · ширина · поле · число · строка файла». Цифру в находку берёшь из файла замера (перечитай строку по номеру), не из памяти.
- **[group-12]** Линза сдаётся сразу после проверки (group-24), до перехода к следующей.

## 4. Бюджет кадров

- **[group-13]** Норма каждой линзы — из её файла агента для текущей `DEPTH` (в быстрой проверке — норма `quick`, нет её — норма `lite`). Потолок группы — 40 уникальных кадров, просмотренных Read-ом.
- **[group-14]** Кадр, по которому ты проверил пункты нескольких линз, засчитывается каждой. Первый экран 390 главной, разобранный для `visual`, `typography` и `color`, даёт +1 каждой.
- **[group-15]** Порядок плана: сначала общие кадры (первые экраны 390 и 1440 главной и продуктовых страниц, куски 390 главной), затем особые кадры линз: листы `vision` у `color`, `measure/mobile/*.jpg` у `mobile`, листы `measure/perf/<pid>-film.jpg` у `perf`, попапы `measure/forms/*.jpg` у `forms`, кадры проб у `stability` и `a11y`.
- **[group-16]** Пример: `visual, typography, color` в standard, нормы 20, 20 и 20. Общие 16 кадров (первые экраны и куски главной и трёх продуктовых страниц на 390 и 1440) + 4 своих у `visual` (лист картинок, кадр наведения) + 4 у `typography` (заголовки на 320) + 4 у `color` (листы `vision`) = 28 уникальных, нормы всех трёх выполнены. В lite у тех же линз норма 10 — хватает общих кадров и 1–2 особых.
- **[group-17]** Сумма норм не помещается в 40 и с общими кадрами — урезай особые кадры пропорционально нормам. У урезанной линзы `coverage.screenshots_viewed` — честное число, в `not_checked` — «кадров N при норме M: общий потолок группы 40».
- **[group-18]** В `notes/<lens>.md` каждой линзы — список просмотренных кадров (пути). Критик сверяет `screenshots_viewed` с ним.

## 5. Инструменты по линзе

- **[group-19]** Скрипты — по разделу «Защита» файла линзы, которую сейчас выполняешь, и по `core.md` §2. Скрипты замеров не запускает ни одна линза группы (`agents/group.md` §4): нет данных — `not_checked` и строка «оркестратору: перезапустить <скрипт> для <pid> — <причина>». Разрешено: `probe.mjs`, `validate.mjs`, `state.mjs`, `show.mjs`; перемер части страниц — `mobile.mjs` или `vision.mjs` с `--pages <pid> --subset`, если файл линзы это разрешает.
- **[group-20]** Скрипты и пробы — по одному, без запуска в фоне: у машины два браузерных слота на всех агентов. Код 75 у `probe` — повтори тот же вызов один раз; снова 75 — пункт в `not_checked` этой линзы.
- **[group-21]** Одно правило навыков и сети для всех групп:
  - WebFetch и WebSearch — только пока выполняешь линзу, у которой они есть в строке `tools:` её файла агента (сейчас `product`, `facts`, `seo-content`, `legal`, `visitor`); свои внешние запросы — разделом «Внешние запросы» в `notes/<lens>.md` этой линзы;
  - Skill — только пока выполняешь линзу, у которой `Skill` есть в строке `tools:` её файла, и только навыки из раздела «Навыки» её файла; имя навыка — в `skills_used` этой линзы;
  - экономный режим (`DEPTH=lite` или `brief.json → models: "economy"`) — навыки не вызываешь ни у одной линзы и их файлы не читаешь: работаешь по справочникам Ревизора (поправки к навыкам уже в чек-листах), `skills_used: []`, в `notes/<lens>.md` — «навыки не вызывались: экономный режим».
  - Файлы проб — `<RUN>/probe-js/<lens>-*.js|css|html` и файлы проверки правок `<RUN>/probe-js/fix-<lens>-*` с именем линзы, для которой проба.

## 6. Владельцы и сдача линзы

- **[group-22]** Пометка в скобках сужает линзу. «ux — только сценарии форм»: `ux` проходит путь кнопка → попап → поля → ошибка пустой формы → «спасибо» и возврат; остальные разделы её чек-листа — одной строкой в `not_checked` «вне темы быстрой проверки».
- **[group-23]** Одна проблема — одна находка у линзы-владельца по `_owners.md`. Владелец в группе — находку пишешь в его файл, по его норме и с его id, даже если заметил на другой линзе. Владельца в группе нет — строка в `for_other_lenses` той линзы, где заметил. Две находки на одно место из двух линз группы не бывает.
- **[group-24]** Сдача линзы: Write `findings/<lens>.json` (большой объём — `<lens>.partN.json`, сквозная нумерация) → `node "<ROOT>/scripts/validate.mjs" --file "<RUN>/findings/<lens>.json"` → исправить до кода 0 → Write `notes/<lens>.md` по шаблону её чек-листа → `node "<ROOT>/scripts/state.mjs" --run "<RUN>" --set lens:<lens>=ok`. Второй круг — `<lens>.r2.json`, id `<lens>-r2-NN`, ключ `r2:<lens>` (второй круг `state.mjs` обычно запускает линзами по одной).
- **[group-25]** Шапка файла: `lens` — эта линза, `agent: "revizor:group"`, `round`, `profile`, `design_read` (одна строка на группу, повтори в каждом файле), `skills_used` — навыки этой линзы, `coverage` — страницы, ширины, состояния, пункты чек-листа и кадры этой линзы.
- **[group-26]** Сильные стороны — у каждой линзы свои, не больше 3, одна и та же сильная сторона не повторяется в двух файлах группы.

## 7. Частичная сдача, контекст и сбои

- **[group-27]** Нет ни `agents/<lens>.md`, ни `checklists/<lens>.md` — `findings/<lens>.json` с пустым `findings`, в `not_checked` — «нет справочника линзы <lens>», `lens:<lens>=partial`. Линзу по догадке не выдумываешь.
- **[group-28]** Доля контекста на линзу — примерно 1/N остатка после общего чтения (N — несданные линзы группы). Линза съела свою долю, а разделы чек-листа остались — сдай её частично: файл с проверенным, честный `coverage.checklist_done`, в `not_checked` — непройденные разделы, отметка `lens:<lens>=partial`; переходи к следующей. Так каждая линза получает своё время, и повторный запуск группы не нужен (на подписке Pro он стоит ещё одного чтения `core.md` и общих замеров). Контекст кончается, а линзы не начаты — их не трогаешь: ни файла, ни отметки; оркестратор запустит группу снова, новый запуск начнёт с них (§2).
- **[group-29]** Нет файла замеров, на котором стоит линза (`perf.json` у `perf`, `headers.json` у `security`), — по правилу её файла агента: пункты в `not_checked`, строка оркестратору. Цифр, которых нет в замерах, не пишешь.
- **[group-30]** Упал скрипт или проба у одной линзы — остальные линзы продолжаются, сбой — строкой в `not_checked` этой линзы.

## 8. Ответ оркестратору

Не длиннее 15 строк: строка на линзу (число по важности и главная находка), затем «не проверено», строки «оркестратору: …» и пути. Образец (вымышленный):

```
LENSES=a11y,perf,stability
a11y: P0 0 · P1 2 · P2 5 · P3 3 — a11y-01 «Фокус не виден на 12 из 14 ссылок меню на 1440 px»
perf: P0 0 · P1 1 · P2 3 · P3 2 — perf-01 «LCP на 390 px 6,8 с: картинка героя 2,9 МБ с loading=lazy»
stability: сдана раньше
Не проверено: perf — поля CrUX нет (квота PSI); a11y — зум 200 % на 390 (проба упала по таймауту).
Оркестратору: перезапустить perf.mjs для p04 — страницы нет в perf.json.
Файлы: <RUN>/findings/a11y.json, perf.json, stability.json; <RUN>/notes/
```

## 9. Самопроверка перед ответом

- [ ] У каждой линзы из `LENSES` файл прошёл `validate` или линза оставлена несданной по group-28.
- [ ] В каждом файле `lens` — своя линза, `agent: "revizor:group"`, id своей линзы.
- [ ] Ни одной находки в файле линзы, которая ей не владеет.
- [ ] Нормы каждой линзы — из её чек-листа.
- [ ] `screenshots_viewed` каждой линзы не больше числа кадров, просмотренных Read-ом; уникальных кадров на группу ≤ 40.
- [ ] Большие замеры читал частями (group-11), ни одного файла > 100 КБ целиком.
- [ ] Скрипты замеров не запускал; WebFetch, WebSearch и навыки — только у линз, которым они есть в `tools:`, и не в экономном режиме.
- [ ] Отметки в `state.json` стоят по линзам (`lens:<lens>`), не по группе.
