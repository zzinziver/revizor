# Чек-лист скептика

Процедура для `revizor:skeptic`. Скептик перепроверяет находки линз и пытается их опровергнуть. Его главная польза — калибровка: отклоняет он немного, зато часто правит важность, цифру и правку. Исходная позиция: «не воспроизвёл = rejected».

Формат вывода — `verify/<lens>.json` (образец — агент `skeptic.md` §7), поля находок — `findings-format.md`, важность — `severity.md`, ложные срабатывания — `pitfalls.md` (§8 — инструменты, §9 — по линзам).

## 1. Объём: что проверять

| Промт (`SCOPE=`) | Режим | Обязательно | Выборочно |
|---|---|---|---|
| `P0` | lite | все P0 | — |
| `P0-P1 (+P2 выборочно, не меньше 3)` | standard | все P0 и P1 | P2: не меньше 3 на линзу, спорные первыми (большая цифра, слово «нет», правка с удалением); у линзы больше 30 находок — не меньше 15 из P2–P3 |
| `P0-P2` | deep | все P0, P1, P2 | P3: 3 на линзу; у линзы больше 30 находок — не меньше 15 из P3 |
| `P0-P1` | quick | все P0 и P1 | P2: 2 |
| `новые P0-P1` | второй круг | P0–P1 из `findings/<lens>.r2.json` | — |
| `все fixed P0-P1 и все regressed` | recheck (`MODE=recheck`) | §9.1: `fixed` с прежней P0–P1, все `regressed`, все `new` с тегом `regression`, остальные `new` P0–P1 | — |
| `ids:<id,id,…>` | перепроверка по просьбе редактора или критика | только эти id: прочитай свой прежний `verify/<lens>.json` (во втором круге — `.r2.json`), перемерь эти находки двумя путями, замени их вердикты в том же файле, остальные вердикты сохрани без изменений. Здесь `severity_after` — итоговая важность: свод ставит этот вердикт после поправок критика, и он перекрывает повышение критика. Учти довод критика из `critic/round-*.json` и ставь важность по фактам замера. Готово — `state.mjs --set verify:ids=ok`, сбой — `verify:ids=failed`; ключи `verify:<lens>` в этом режиме не меняешь. id вида `<lens>-vNN` (находка скептика) вердикта не получает: исправь её в `added_by_verifier` или убери оттуда | — |

- **[skeptic-01]** Вердикт ставится каждой находке из обязательного объёма. P0–P1 без вердикта уходят в отчёт с пометкой «требует проверки», а для чужой команды снимаются.
- **[skeptic-02]** Находки вне объёма вердикта не получают и идут в отчёт как непроверенные.
- **[skeptic-03]** Сильные стороны (`strengths`) своих линз проверяются все. `clean_checks` — все, что касаются главного сценария (кнопка действия, форма, меню на телефоне, цены), и не меньше 3 остальных.
- **[skeptic-03a]** Линза `facts` в твоих `LENSES` (кроме lite): таблица фактов в `notes/facts.md` — все строки со значением «совпадает? — нет» и 10 строк «да», каждая — Grep значения по `snapshot/<pid>/text.md` той `pid`. Строка «да», которая не сходится, — пропущенная находка (§8).
- **[skeptic-03b]** Переезд (`brief.baseline` есть, кроме lite): сравнение «старое → новое» в `notes/<lens>.md` своих линз — все пункты со статусом «нет», «иначе», «частично» и 10 пунктов «есть».

## 2. Порядок работы

- **[skeptic-04]** Первым читать `verify/<lens>.lint.json` каждой своей линзы. Блокирующие ошибки (`quote_not_found`, `quote_other_page`, `before_not_found`, `no_known_place`, `schema_fatal`) не пустят находку в отчёт без твоего `confirmed` или `adjusted`. Ремонтируемые (`shot_missing`, `box_out_of_bounds`, `box_not_in_shot`, `shot_outside_run`, `pid_unknown`) `merge.mjs` уберёт сам, находка останется без кадра.
- **[skeptic-05]** Затем файл линзы целиком (`findings/<lens>.json` или все `.partN.json`, во втором круге `.r2.json`) и её `notes/<lens>.md`.
- **[skeptic-06]** По каждой находке: прочитать `where`, `evidence`, `method`, `norm`. Перемерить **тем же методом** (§3), у P0–P1 — ещё вторым независимым путём ([skeptic-11a]). Сравнить цифру, место, ширину, состояние.
- **[skeptic-07]** Сверить находку с `brief.json`: `owner_decisions`, `not_a_bug_at_stage`, `do_not_suggest`, `do_not_touch`, `known_issues`, `verified_facts`, `stage`. Совпало с решением владельца или стадией — `rejected`. Находка повторяет запись `known_issues` (владелец о проблеме знает) — тоже `rejected`, `note`: «известно владельцу: <запись брифа>»; редактор посчитает такие находки в разделе метода.
- **[skeptic-08]** Проверить правку (`fix_ok`, §5) и текст «стало» (`text_ok`, §6).
- **[skeptic-09]** Проверить сильные стороны и `clean_checks` (§7).
- **[skeptic-10]** Записать до 5 пропущенных находок (§8).

## 3. Перемер тем же методом

| `method` находки | Как перемерить |
|---|---|
| `script:<имя>` | открыть `measure/<имя>.json`, найти ту же страницу и ширину, сверить поле и число. Это первый путь; у P0–P1 нужен второй ([skeptic-11a]). `mobile` и `vision` можно перезапустить по одной странице: `node "<ROOT>/scripts/mobile.mjs" --run "<RUN>" --pages <pid> --subset` (флаг `--subset` последним) — результат ляжет в `measure/mobile.subset-<время>.json`, основной файл не тронется. Остальные скрипты замеров не запускать: они перезапишут общий файл |
| `probe` | повторить ту же команду `probe.mjs` с теми же `--pid`, `--width`, действием; сравнить `target_on_top`, `metrics`, `result` |
| `axe` | `measure/axe.json` → правило, страница, число узлов; спорный узел — `probe --expr` по селектору |
| `fetch` | `measure/seo.json`, `headers.json`, `domain.json` → код ответа, заголовок; `raw.html` той страницы |
| `screenshot` | открыть кадр Read-ом, найти место по `box`. Пустой блок, серая карта, пустая картинка или белая полоса в куске — сначала свежий кадр `probe --pid <pid> --width <w> --scroll <y> --shot <имя>.jpg` (ленивая загрузка и `content-visibility` дают пустоты, `pitfalls.md` §8) |
| `dom` | `snapshot/<pid>/dom.html` или `page.json` через Grep; живое значение — `probe --expr "getComputedStyle(document.querySelector('<sel>')).<свойство>"` |
| `manual` | рассуждение без замера: допустимо только для P2–P3 и с `needs_decision`. P0–P1 с `manual` без замера → `rejected` или `adjusted` до P2 с объяснением |

- **[skeptic-11]** Касание проверяется только `probe --tap/--click` (реальный ввод) и полем `target_on_top`. Находка «кнопка работает/не работает» по `element.click()` не доказана.
- **[skeptic-11a]** P0–P1 подтверждаются **вторым независимым путём** (`pitfalls.md` §8). Перечитать тот же `measure/*.json`, на котором стоит находка, — не второй путь: ошибка замера повторится (пустой title принят за 404, вес без Timing-Allow-Origin равен нулю, белый кадр состояния). Второй путь по методу:
  - `script:*`, `axe`, `fetch` — живой `probe` (`--expr`, `status`, `metrics`, `console_errors`), `raw.html` или `dom.html` той страницы, кадр;
  - `screenshot` — `probe` со свежим кадром или `dom.html` (элемент, стиль, размер);
  - `probe`, `dom` — кадр той же страницы и ширины или `raw.html`.

  В `how` — оба пути с цифрами: «measure/seo.json: p04 status 404; probe --pid p04 --no-shot: status 404, final_url тот же». Второй путь противоречит первому → `rejected` или `adjusted` с цифрой второго пути. Второй путь недоступен (живой сайт закрыт, [skeptic-14a]) — `needs_device` или проверка по кадру человека.
- **[skeptic-12]** Цифра перемера отличается от цифры линзы, вывод тот же — `adjusted`, верная цифра — в `how` и в `note` по правилу [skeptic-33]. Вывод другой — `rejected` или `adjusted` с другой важностью.
- **[skeptic-13]** Дефект зависит от WebKit, живого телефона, кабинета или отправки формы, а в headless Chromium не воспроизводится и не опровергается → `needs_device`. В `note` — проверка для человека по формуле `human-checks.md` («устройство · где · что сделать · что считать проблемой · сколько времени»).
- **[skeptic-14]** Не воспроизвёл и причины не нашёл → `rejected`, `note`: «не воспроизвелось: <что сделал, что увидел>». Важный факт, который не смог проверить, тоже `rejected`.
- **[skeptic-14a]** Сайт не пускает скрипты: `probe` вернул код 1 (страница не загрузилась) или 3 (адрес отклонён, защита от ботов), `pid` есть в `snapshot/snapshot.json → summary.blocked_pages`, есть папка `<RUN>/manual/` или строка `MANUAL_SHOTS` в промте. Это не «не воспроизвелось»: [skeptic-14] здесь не действует.
  - Перемерь по тому, что есть: кадры `manual/` (снимки человека), `snapshot/<pid>/shots/`, `raw.html`, `text.md`.
  - Находка по кадру человека (`manual/…` в `shot` или `evidence`): дефект виден на кадре без догадок — `confirmed`, `how`: «кадр manual/<файл>: <что видно>; живой перемер невозможен (probe код 3)». Не виден или зависит от действия — `needs_device`.
  - Проверить нечем — `needs_device` с проверкой для человека.
  - В ответ оркестратору одна строка: «живой перемер невозможен: <pid>, код <n>, проверено по кадрам: N».

## 4. Пересказ шире источника

Главная систематическая ошибка линз. Скрипт её не ловит, ловишь ты. По каждой находке:

- **[skeptic-15]** Обобщение: «на каждой странице», «на всех карточках», «везде» — посчитай сам (Grep по `snapshot/*/text.md`, замер по всем `pid`). Проверено 3 из 20 — так и пиши: «на 3 проверенных страницах из 3».
- **[skeptic-16]** Положение: «под первым экраном» против «в первом экране, под баннером» — сверь с `box` и высотой окна (390 → 844, 1440 → 900; ноутбук 1366 × 657).
- **[skeptic-17]** Счёт: «шесть отзывов» при четырёх, «три тарифа» при двух. Пересчитай по кадру и `text.md`.
- **[skeptic-18]** Причина: «из-за скрипта платформы», «из-за медленного сервера» — без замера это догадка; убрать из текста или `rejected`, если на ней держится вывод.
- **[skeptic-19]** Оценочные слова в `title/problem`: «неудобно», «устаревший», «некрасиво» — переписать в факт (`adjusted`, новая формулировка в `note`).
- **[skeptic-20]** Утверждение о том, что не снимали: «маска ломает номер», «письмо после заявки не приходит», «заявка теряется» — без ввода и отправки это не проверено → `needs_device` или `rejected`.
- **[skeptic-21]** Цитата: дословно и с **той** страницы, что в `where` (lint это проверил; при `quote_other_page` найди Grep-ом страницу, где цитата стоит, и действуй по [skeptic-33]).
- **[skeptic-22]** «Нет X»: ищи сам в `raw.html`, `dom.html`, `text.md` (строки `[свёрнуто]`, `[скрыто]`, `[невидимо]`, `[декор]`), в попапах (`measure/forms/*.jpg`) и на соседних страницах. Нашёл обычной строкой или с `[свёрнуто]` — `rejected`. Метки: `[невидимо]` — блок прозрачен или скрыт, посетитель его не видит; `[скрыто]` — тоже не показывается; `[декор]` — посетитель видит, скринридер не читает. «Нет X» при X только с `[невидимо]` или `[скрыто]` верно для посетителя (`confirmed`, в `how` — метка и строка); X с `[декор]` — для `a11y` его нет, для остальных линз есть.

## 5. Правка: `fix_ok`

- **[skeptic-23]** `fix_ok: true` — правка выполнима на платформе (`brief.platform`, `platforms/<id>.md`), конкретна (что, где, готовый текст или CSS) и ничего не ломает.
- **[skeptic-24]** `fix_ok: false`, если: правка удаляет то, что держит другое (пустые заголовки от анимации, блок плавного появления, прикрывающий скачок вёрстки); неразрывные пробелы склеивают длинные слова на 320–390; добавляет `preload` к картинке, которую не показывают; меняет обработчик фокуса так, что ломается касание; требует того, чего платформа не умеет; добавляет «ключи в alt»; включает то, что уже работает (HTTP/2, сжатие). В `note` — выполнимая замена.
- **[skeptic-25]** P0–P1 с правкой CSS или HTML и `fix_verified: false`: проверь подменой сам — файл `<RUN>/probe-js/skeptic-<id>.css` (или `.html`) и `probe --pid <pid> --width <w> --css "<RUN>/probe-js/skeptic-<id>.css"`. Ответ `before`/`after` покажет, стало ли лучше и не уехало ли соседнее. Итог — в `how` с кадром «после» («подмена: overflow 34 → 0 px на 390, кадр probe/p02-390-fix.jpg»).
- **[skeptic-26]** Правка спорит с `owner_decisions` или `do_not_suggest` → `fix_ok: false`, в `note` — замена в рамках решения или «правки нет: решение владельца».

## 6. Текст «стало»: `text_ok`

Для находок с полем `after` (тексты, title, description, H1, подписи кнопок):

- **[skeptic-27]** Прогони строки: все `after` своего объёма Write-ом в `<RUN>/probe-js/skeptic-text-<METHOD>.txt`, по одной на строку, затем `node "<ROOT>/scripts/textscan.mjs" --run "<RUN>" --text-file "<RUN>/probe-js/skeptic-text-<METHOD>.txt"`. Текст не идёт в командную строку: цитаты и кавычки чистить не нужно. Код 4 (найдены P0–P1) → `text_ok: false` у находки, чья строка названа в выводе.
- **[skeptic-28]** `text_ok: false` и без скрипта, если текст: добавляет оговорку («обычно», «как правило», «возможно»); выдумывает факт (цена, срок, число клиентов, регалия, отзыв, которых нет в `text.md` и `verified_facts`); держится на вкусе; спорит с решением владельца; хуже исходника (длиннее без пользы, канцелярит, «не X, а Y»); ломает норму (title длиннее ~70 знаков для Яндекса, ключ в неестественной форме).
- **[skeptic-29]** При `text_ok: false` в `note` — исправленный вариант. Его тоже прогони через `textscan --text-file` ([skeptic-27]). Юридические тексты (согласия, оферта, политика) навыками и словарями не переписываются: только сверка с первоисточником.

## 7. Сильные стороны и «чисто»

- **[skeptic-30]** Сильная сторона — то, что помогает посетителю дойти до действия, и у неё есть цифра. «Единый стиль», «аккуратная вёрстка», «современный дизайн», «удобная навигация» без замера → `wrong_strengths` с причиной.
- **[skeptic-31]** Сильная сторона, которую опровергает замер (кнопка «в первом экране на всех страницах», а на 2 из 7 её нет на 390) → `wrong_strengths`.
- **[skeptic-32]** `clean_checks`: перепроверь тем же методом. «Чисто» без выборки («ошибок нет» без числа страниц) или с ошибкой → `wrong_clean_checks` с тем, что нашёл. Если там дефект — это ещё и пропущенная находка (§8).

## 8. Неверное доказательство, пропущенное, замены

- **[skeptic-33]** Вывод находки верен, но в `evidence` неверная цифра или цитата:
  - место (`where`) верное — `adjusted`, `note` начинается с `evidence:` и даёт верное значение с источником: «evidence: верно 3,1:1 (measure/contrast.json p03@390; probe --expr), вывод тот же». Верное значение должно стоять и в `how`. Редактор поставит его в `title` и `problem`, а неверное уберёт из `evidence` (новых чисел в `evidence` скрипт не пускает, замер виден в строке «как проверено»);
  - цитата или дефект на другой странице (`quote_other_page`), неверная `pid` или ширина в `where` — поле `where` редактор не меняет: `rejected` с `note` «заменена на <lens>-vNN: <что не так>» и исправленная находка в `added_by_verifier` с тем же смыслом и верным местом. Замена идёт в отчёт без вердикта: P0–P1 — с пометкой «требует проверки», для чужой команды снимается. Поэтому замена — только когда неверно место; неверное число при верном месте — `adjusted`.
- **[skeptic-34]** До 5 пропущенных находок на линзу — только с собственным замером (`method` не `manual`), в формате `findings-format.md`, id `<lens>-v01`, `<lens>-v02`… Замены по [skeptic-33] в этот лимит не входят. Во втором круге номера продолжают первый (были `mobile-v01`…`v03` в `verify/mobile.json` — новые с `mobile-v04`): повтор id `validate.mjs --run --all` считает ошибкой, а `merge.mjs` снимает повтор.
- **[skeptic-34a]** Свою находку (и замену) проверяешь так же строго, как чужую. Без записи в `verdicts` она `unverified` (P0–P1 — с пометкой «требует проверки»); подтверждение — отдельная запись в `verdicts` с тем же `id` (`mobile-v01`) и `how` со вторым независимым путём ([skeptic-11a]). `merge.mjs` прогоняет по ней lint и отклоняет при блокирующей ошибке (цитаты нет на странице, страницы нет в снимке), а критик выборочно сверяет 3 таких находки.
  - Каждую цитату в «…» найди Grep-ом в `snapshot/<pid>/text.md` (или `raw.html`, `dom.html`) той `pid`, что в `where`; в `evidence` — файл и строка: «snapshot/p02/text.md, строка 41». Цитаты нет дословно — не пиши её.
  - Рамку `box` сверь с кадром по `snapshot/<pid>/shots/index.json`: в CSS px документа рамка лежит в пределах `width` и между `y0` и `y1` этого кадра; в пикселях файла (`box_space: "image"`) — в пределах `img_w × img_h`.
  - У P0–P1 — два пути в `evidence`, как в [skeptic-11a]. Правку CSS или HTML у своей P0–P1 проверь подменой ([skeptic-25]) и заполни `fix_verified: true`, `fix_check`, `fix_shot` (кадр «после» от RUN, обычно `probe/<имя>.jpg`), `fix_box` `[x, y, w, h]` с `fix_box_space: "image"` для кадров `probe/`, `fix_viewport` (ширина кадра) — `findings-format.md` §3. В вердиктах по чужим находкам этих полей нет: `merge.mjs` их не переносит, кадр «после» — путём в `how`.
- **[skeptic-35]** Пропущенное в чужой зоне не добавлять: строка в `note` ближайшего вердикта или в ответ оркестратору.

## 9. Особые линзы и режимы

- **[skeptic-36]** `legal`: каждая находка ссылается на действующую редакцию нормы (закон, статья, дата редакции, ссылка на первоисточник). Нет ссылки или редакция устарела → `rejected`. Сверка — WebFetch первоисточника (официальные публикации законов, сайт регулятора). Формулировка — «решение владельца, лучше с юристом». Заявления о льготах и особых условиях — вопрос владельцу, не P0.
- **[skeptic-37]** `security`: уверенность по шкале 1–10, в отчёт идёт только 8 и выше. Ниже 8 → `rejected` с оценкой в `note`. Ограничение платформы (заголовки на конструкторе) — `adjusted` до P3. «Критично» — только при доказанной уязвимости. Верный вывод с неверной причиной → `adjusted` с причиной из замера.
- **[skeptic-38]** `perf`: лабораторные цифры относительны; `machine_slow` или троттлинг на слабой машине — P0–P1 только по полевым данным (CrUX/PSI) или по поломке (белый экран, LCP-картинка с `loading=lazy`). Иначе `adjusted` вниз.
- **[skeptic-39]** `a11y` и `mobile`: цели касания — 24 px (WCAG 2.5.8, AA) и 44 px (рекомендация Apple); находка обязана назвать норму. Ссылки внутри предложений из 2.5.8 исключены. 44 × 44 — это AAA (2.5.5), P0–P1 по ней не ставятся.
- **[skeptic-40]** `copy`: тире — штатная пунктуация, «ё» — не ошибка, английские правила навыков к русскому не применяются. Тексты в свёрнутых блоках и вкладках — часть страницы.
- **[skeptic-41]** `facts`: сноска может описывать другое, перечень может быть во вкладке соседней страницы, «смысл изменён» может оказаться другими словами того же смысла. Прочитай оба места целиком.
- **[skeptic-42]** Вкус, поданный как дефект → `adjusted`, `severity_after: "P3"`, `note`: «вкус: на решение владельца».
- **[skeptic-43]** Второй круг (`ROUND=2`): файл `verify/<lens>.r2.json`, вердикты только на id из `findings/<lens>.r2.json`. Проверь заодно, что новая находка не дублирует находку первого круга (`node "<ROOT>/scripts/show.mjs" --run "<RUN>" --lens <lens>`): дубль → `rejected`, `note`: «дубль <id>».

### 9.1 Режим recheck (`MODE=recheck`)

- **[skeptic-44]** Входы: `recheck/plan.json` (`items` по `uid`: прежние `title`, `severity`, `where`, `method`, `fix_check`), файлы `recheck/<группа>.json` и `recheck/fresh.json` агентов `rechecker`.
- **[skeptic-45]** Обязательный объём, без выборки:
  - все `items` со статусом `fixed`, у которых прежняя важность P0 или P1;
  - все `regressed` любой важности;
  - все находки из поля `new` с тегом `regression` любой важности (поломки от правок, исходная позиция — «не подтвердилось»);
  - остальные `new` P0–P1.
- **[skeptic-46]** `fixed` перемеряется тем же методом, что в плане, на тех же страницах и ширинах. Исправление подтвердилось → `confirmed`; не подтвердилось → `rejected` (`recheck.mjs --collect` поставит `not_fixed`).
- **[skeptic-47]** `regressed` и `new`: стало хуже по замеру (для P0–P1 — двумя путями, [skeptic-11a]) → `confirmed`; нет → `rejected`; зависит от устройства — `needs_device`.
- **[skeptic-48]** Файл — `verify/recheck.json`: `{ "lens": "recheck", "checked": N, "verdicts": [ { "uid": "R-1a2b3c4d", "verdict": "confirmed|rejected|needs_device", "how": "…", "note": "…" } ] }`. Вердикт по новой находке — с ключом `"id": "new:<группа>:<номер в массиве new с 0>"` (`new:g2:0`, `new:fresh:1`; группа — имя файла без `.json`). `recheck.mjs --collect` применяет эти вердикты сам (отклонённые новые — в `result.json → rejected_new`, отклонённая регрессия прежней находки — `items[].regression_rejected`, регрессия без твоего вердикта — `regressions[].unverified`); отклонённые перечисли в ответе для сведения.

## 11. Самопроверка перед сдачей

- **[skeptic-49]** У каждого P0–P1 своих линз есть вердикт; `how` у каждого вердикта — чем перемерил (файл и поле, команда, кадр); у `confirmed` и `adjusted` P0–P1 — два пути.
- **[skeptic-50]** У `adjusted`, `rejected`, `needs_device` есть `note`: почему и что поправлено. Неверная цифра или цитата — `note` с `evidence:` ([skeptic-33]).
- **[skeptic-51]** `refuted` не используется — только `rejected`.
- **[skeptic-52]** `node "<ROOT>/scripts/validate.mjs" --file "<RUN>/verify/<lens>.json"` проходит с кодом 0 для каждого файла. Файл есть у каждой линзы из `LENSES`, даже если в объёме не нашлось ни одной находки (`"checked": 0, "verdicts": []` и проверенные сильные стороны): по наличию файла оркестратор видит, что линза перепроверена.
- **[skeptic-53]** В `note` и в `added_by_verifier` нет слов из запрет-листа (`tone.md`, раздел «Запрещено»): твоя правка тоже без «возможно», «является», «не X, а Y».
- **[skeptic-54]** Каждая цитата в «…» в `added_by_verifier` найдена Grep-ом, файл и строка — в `evidence`; рамки в пределах кадра.
