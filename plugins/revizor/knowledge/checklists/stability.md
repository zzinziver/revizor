# Чек-лист `stability` — стабильность и код

Формат пункта: **[stability-NN] что проверить** — как проверить (файл и поле замера, проба, кадр) — норма — ложные срабатывания.
Пути — от RUN. `page.json`, `raw.html`, `dom.html`, `text.md` лежат в `snapshot/<pid>/`. Сводка ошибок всех страниц — `snapshot/errors.json` (по `pid`: `exceptions[]`, `console[]` с `type`, `failed[]`, `http_errors[]` — у каждой записи `widths`; `induced_exceptions` — вызваны нашей страховкой). `page.json` реальной страницы — сотни КБ: только Grep по ключу и Read с `offset`/`limit`, целиком не читать. Ошибки в `page.json` уже очищены от вызванных нашей блокировкой (они отдельно в `caused_by_blocking`).
«Главная» в командах — `home`; при строке `PAGES=` в промте — первая pid из неё (главной в таком прогоне может не быть).

Главный вопрос линзы: работает ли код у посетителя и что сломается, если один скрипт, шрифт или сервис не загрузится. Главное в находках по стабильности — цепочки «ошибка → что потерял бизнес» (примеры вымышленные):
- виджет онлайн-чата падал при загрузке, обработчик кнопки «Записаться» так и не повесился — форма уходила без телефона;
- в коде видно, что обработчик кнопки проверяет поля, — но на странице до него не доходило: «код есть» не значит «код работает», проверяй на загруженной странице;
- блоки первого экрана появлялись скриптом при прокрутке: когда скрипт не загрузился, посетитель видел пустую страницу с шапкой.

## A. Ошибки при загрузке

**[stability-01] Исключения JS** — `snapshot/errors.json → items[].exceptions[]` (`text`, `widths`), `summary.pages_with_exceptions`; подробности — Grep `page.json` (`"exceptions": \[` -A 8, `loads.<ширина>.exceptions`) — норма: 0 — ложные: `induced_exceptions` и `caused_by_blocking.exceptions` (сломалось из-за нашей страховки или блокировки счётчика) — не находка; исключение из стороннего скрипта (чат, виджет) — находка, если ломает видимое; «Script error.» без файла — ошибка в чужом скрипте, источник не виден.

**[stability-02] console.error** — `errors.json → items[].console[]` с `type: "error"` или `"log-error"` (предупреждения там только числом — `counts.console_warnings`) — норма: 0 своих ошибок — ложные: `warning` и `assert` — не ошибки; сообщения с адресами из `blocked` и `ERR_BLOCKED_BY_CLIENT` — наша блокировка; 404 фавиконки — пункт `seo-tech`.

**[stability-03] Ошибка повторяется** — та же ошибка на 2+ загрузках: несколько ширин в `widths` у записи `errors.json`, или проба `probe.mjs --pid <pid> --width 390 --no-shot` → `console[]` с `phase: "load"` и типом `error`/`log-error`, `exceptions` — норма: находку P0–P2 строишь только на повторившейся ошибке — ложные: разовая ошибка сети или CDN; ошибка только на одной ширине — см. stability-12; `exceptions_induced` пробы — наша страховка.

**[stability-04] Свои запросы с ошибкой 4xx/5xx** — `errors.json → items[].http_errors[]` (`url`, `status`, `type`): Script, Stylesheet, Font, Image, XHR, Fetch своего сайта; Grep `page.json` `"status_4xx_5xx"` -A 20 — норма: 0 — ложные: 404 на `favicon.ico` при объявленной иконке — `seo-tech`; 403 от защиты на запрос аналитики; 401 у API, который требует входа, — норма.

**[stability-05] Сетевые ошибки** — `errors.json → items[].failed[]` (`url`, `error`): `ERR_NAME_NOT_RESOLVED`, `ERR_CONNECTION_REFUSED`, `ERR_CERT_*`, `ERR_TIMED_OUT` — норма: 0 — ложные: `ERR_BLOCKED_BY_CLIENT` (наша страховка) и `ERR_ABORTED` (браузер отменил сам) скрипт уже убрал. Скрипт с домена, который не резолвится, — ещё и `for_other_lenses` → `security` (домен можно перерегистрировать).

**[stability-06] Битые картинки** — Grep `page.json` `"broken"` -B 3 (`images.broken`, `images.list[].broken`), `http_errors[]` с `type: "Image"`, кадр места (`box`) — норма: 0 после прокрутки — ложные: картинка с `loading=lazy`, которую снимок не докрутил, — пустая, но не битая (`broken` проверяет `complete && naturalWidth === 0`).

**[stability-07] Ошибки из-за блокировки счётчиков** — `caused_by_blocking.{console, exceptions}`, `loads.*.console_blocked_by_revizor`, `blocked.analytics|widget` (Grep `page.json`) — норма: без счётчика сайт работает — ложные: сама ошибка из-за нашей блокировки находкой не считается. Если без счётчика не открывается меню или форма (проверь `probe --tap`), у посетителей с блокировщиком рекламы будет то же — находка P2.

**[stability-08] Попытки записи при загрузке** — Grep `page.json` `"write"` -A 12 (`blocked.write.{n, sample[]}`: `url`, `method`, `phase`) — норма: при простом открытии страница не шлёт POST, кроме аналитики — ложные: сайт грузит содержимое POST-ом (SPA) — снимок без содержимого; это ограничение замера: строка в `not_checked` и «оркестратору: перезапуск с `--allow-load-posts`», находкой не считается.

## B. Ошибки при действиях

База для каждого пункта раздела — ошибки загрузки этой страницы на этой ширине (`errors.json`) или тот же вызов `probe` без `--tap`. Ошибка при действии — `console[]` с `phase: "interact"` и типом `error` или `log-error`, плюс исключение в `exceptions`, которого нет в базе. Предупреждения (`warning`) не считаются.

**[stability-09] Касание бургера** — `mobile.json → burger[].toggle.sel`, `opened` (нет `mobile.json` — Grep `dom.html` на `aria-expanded`, `aria-controls`, `burger|menu-toggle|hamburger`); проба `probe.mjs --pid <pid> --width 390 --tap "<селектор бургера>" --shot stability-burger.jpg` → `console[]` (`phase: "interact"`), `exceptions`, `actions[].target_on_top`, кадр — норма: меню открылось, новых ошибок нет — ложные: не открылось из-за слоя сверху (`target_on_top: false`) — это `mobile`.

**[stability-10] Кнопки попапов** — `forms.json → pages[].toggles[].tapped[]` (`sel`, `effect`, `hit_ok`, `covered_by`, `refused`, `guard_cut[]`, `requests[]`), `toggles[].skipped`, `toggles[].unsafe[]`; проба `--tap "<sel>"` → ошибки с `phase: "interact"`, кадр — норма: попап открылся, ошибок нет — ложные: `effect: "navigation"` — кнопка ведёт на страницу, переход оборван страховкой; это норма для ссылки. `request` — кнопка отправила разрешённый запрос, она живая; на экране ничего не изменилось — подсказка `toggle-request` у `forms`, не находка stability. `blocked_by_guard` — касание или запрос оборвала страховка Ревизора: не находка. `not-tapped` — кнопку закрывает слой (`covered_by`, `covered_text`), касания не было: строка в `for_other_lenses` для `mobile` (или `forms`), отказом попапа не считай; пробой такие кнопки не жмёшь — касание уйдёт в слой сверху. `skipped: "unsafe"`, `unsafe[]`, `refused` и прочие `skipped` — касания не было, пробой не жмёшь, `not_checked`. Подсказки `items[].check` `toggle-*` — владелец в `lens` (`forms`, `mobile`), не дублируй их. Находка — только `none` с ошибкой JS или без видимого отклика на кадре.

**[stability-11] Вкладки, аккордеоны, слайдеры** — селекторы из `dom.html` (`[role=tab]`, `summary`, `[aria-expanded]`, стрелки слайдера); проба `--tap` по 1–2 на странице — норма: открывается, ошибок нет — ложные: аккордеон на `<details>` работает без JS.

**[stability-12] Ошибка только на одной ширине** — `errors.json → items[].exceptions[].widths` (все ширины снимка); в `page.json` — `loads.<ширина>.exceptions` (`by_width` есть только для 390 и 1440, ширина 768 — только в `loads.768`) — норма: одинаково на всех ширинах — ложные: скрипт, который подключается только на телефоне, — проверь `scripts.list` на разных ширинах. Ошибка только на одной ширине — признак инициализации по брейкпоинту.

**[stability-13] Двойная активация и повторная инициализация** — проба `--tap` по бургеру: меню открылось и сразу закрылось (кадр после 500 мс), или `stability-dom.js` → `scripts_twice` (один файл подключён дважды), две версии библиотеки (`headers.json → libraries[]` одного имени, `stability-dom.js` → `jquery`) — норма: одно подключение, одна версия — ложные: один файл с разным содержимым для двух виджетов.

**[stability-14] Калькулятор** — поля калькулятора вне форм с контактами (`forms.json → calculators[]`: `fields`, `outputs`, `in_contact_form`, готовая команда `probe_example`; `facts` ведёт арифметику); проба `--fill "<селектор>=<значение>" --read "<селектор итога>"` с вводом через запятую и через точку → `console[]` (`phase: "interact"`), `exceptions` — норма: ошибок нет, итог меняется — ложные: ввод в поле внутри формы с телефоном скрипт откажет (`refused`) — это страховка. Нет `forms.json` — `not_checked`.

## C. Отказоустойчивость

Пробы раздела — на главной и одной продуктовой странице. Основной скрипт — самый большой свой JS (`perf.json → detail.mobile.top`, иначе Grep `page.json` `"scripts"` -A 40).

**[stability-15] Без основного скрипта** — проба `probe.mjs --pid <главная> --width 390 --block "*/<основной-файл>.js" --shot stability-noscript-main.jpg`; кандидаты — `perf.json → items[].hidden_until_js[]`, `white_screen` — норма: текст первого экрана и кнопка действия видны; меню и формы могут не работать, но страница не пустая — ложные: SPA, где весь контент рисует скрипт, — тогда это `seo-tech` (рендер без JS) и P2 здесь, если нет запасного текста.

**[stability-16] Без веб-шрифтов** — `probe.mjs --pid <главная> --width 390 --block "*.woff2,*.woff,*.ttf,*.otf" --shot stability-nofonts.jpg` — норма: текст виден запасным шрифтом сразу, иконки понятны — ложные: иконочный шрифт без запасного — находка, если иконка — единственная подпись кнопки.

**[stability-17] Без JavaScript** — `probe.mjs --pid <главная> --width 390 --no-js --shot stability-nojs.jpg` — норма: видны H1, основной текст, контакты — ложные: интерактивные блоки без JS не обязаны работать; код ответа и рендер для роботов — `seo-tech`.

**[stability-18] Без зарубежных сервисов (рынок РФ)** — `brief.market.value` = ru или mixed; `probe.mjs --pid <главная> --width 390 --block "*.googleapis.com*,*.gstatic.com*,*.google.com*,*.googletagmanager.com*,*.youtube.com*,*.recaptcha.net*,*.cloudflare.com*,*.jsdelivr.net*" --shot stability-noforeign.jpg` (оставь только хосты, которые есть в `network.third_party_hosts`) — норма: первый экран, меню, шрифты (запасные) и форма видны — ложные: форма с reCAPTCHA без капчи не отправится — запиши как риск, отправку не проверяй.

**[stability-19] Мёртвые виджеты** — Grep `page.json` `"iframes"` -A 15 (`src`), `errors.json → http_errors[]` и `failed[]` по хосту виджета, кадр места — норма: виджет (отзывы, карта, онлайн-запись, лента соцсети) показывает содержимое — ложные: чат и коллтрекинг заблокированы нашей страховкой (`blocked.widget`) — их пустое место не находка; карта серым прямоугольником в headless — артефакт съёмки, проверь кадром пробы с `--wait 3000`.

**[stability-39] Скрипт не выполнился — форма уходит пустой** — проба `stability-forms.js` на странице с формой заявки дважды: как есть и с `--block "*/<основной-файл>.js"`; ничего не нажимать — норма: без скрипта у формы нет рабочей обычной отправки (нет `action` или кнопок `type=submit`), или обязательные поля помечены `required` и браузер не пустит пустую форму — ложные: форма, которую отправляет сторонний сервис во `<iframe>`, — вне пробы; `required` на месте — пустой не уйдёт. Риск: без скрипта `submit_buttons > 0`, `action` указывает на обработчик сайта, `contact_fields > 0`, а `required: 0` — форма уйдёт обычной отправкой без проверки полей: P1, `for_other_lenses` → `forms`. В находке — что будет у посетителя с упавшим скриптом и как сервер это примет (пустая заявка), без отправки.

## D. Код страницы

**[stability-20] `<head>` закрыт раньше времени** — проба `stability-dom.js` → `head_leaked[]` (meta, title, canonical, icon в `<body>`); Grep по `raw.html`: картинка или текст до `</head>` — норма: служебные теги в `<head>` — ложные: `<meta itemprop>` микроразметки в `body` — норма; `<link rel=stylesheet>` в body — допустимо. canonical и robots в body поисковики не учитывают — `for_other_lenses` → `seo-tech`.

**[stability-21] Второй title, второй viewport** — Grep `page.json` `"title_tags"`, `"viewport"` -A 5; `stability-dom.js` → `titles` — норма: по одному — ложные: `<title>` внутри `<svg>` — норма (проба считает все, сверь с `raw.html`).

**[stability-22] DOCTYPE и режим quirks** — Grep `page.json` `"doctype"`, `"quirks"` — норма: `<!DOCTYPE html>`, `quirks: false` — ложные: нет. Quirks ломает вёрстку и размеры — P2.

**[stability-23] Кодировка** — Grep `page.json` `"charset"`; Grep `text.md` на `�` и `????` — норма: `UTF-8` объявлен в первых 1024 байтах — ложные: `????` в цитате кода. Символы вне BMP (эмодзи) превращаются в `????` при неверной кодировке базы платформы.

**[stability-24] `[hidden]` перебит стилем** — `stability-dom.js` → `hidden_shown[]` (элемент с атрибутом `hidden`, у которого `display` не `none`) — норма: пусто; правка — `[hidden]{display:none!important}` в общий CSS — ложные: элемент, который скрипт показывает, снимая `hidden` позже, — проверь кадром, виден ли он посетителю.

**[stability-25] Дубли id** — `stability-dom.js` → `duplicate_ids[]` — норма: id уникальны — ложные: дубль в скрытой копии блока для другой ширины — находка, только если по этому id работает скрипт, якорь или подпись поля (`label for`); иначе `for_other_lenses` → `a11y`.

**[stability-26] Один скрипт подключён дважды** — `stability-dom.js` → `scripts_twice[]`; `perf.json → detail.mobile.duplicates[]` — норма: один раз — ложные: тот же файл в разных версиях (разный `?ver=`) — дубль, правка — убрать старый.

**[stability-27] Глобальные стили задевают чужие блоки** — кадр: ссылки меню подчёркнуты, поля попапа другого вида, чем на странице; проба `stability-who-styles.js` с селектором этого элемента → правило и файл — норма: стиль блока с префиксом своего блока — ложные: базовые стили сайта (`a {color}`) — норма; находка только при видимом дефекте на кадре.

**[stability-28] Невалидный CSS и комментарии** — Grep по `raw.html`: `##[0-9a-fA-F]{3,6}`, `<!--[^>]*<!--` (вложенный комментарий), `<!DOCTYPE` после начала (вложенный), `-->` в видимом тексте (`text.md`) — норма: 0 — ложные: условные комментарии старого IE — мусор, P3.

**[stability-29] HTML-комментарии с именами, путями, пометками `TODO`** — Grep `page.json` `"comments"` -A 12 (`total`, `sample[]`); Grep `raw.html` на `<!--` — норма: в бою нет комментариев с именами людей, путями к макетам и файлам (`C:\`, `/home/`, `.psd`, `.fig`), `TODO`, `FIXME`, «временно», «удалить» — ложные: служебные комментарии платформы (`<!-- Tilda -->`, `wp:` разметка) — норма. Имя человека в отчёте не повторять; ключи и внутренние адреса — `security`.

**[stability-30] Пометки макета и отладки в коде** — Grep `dom.html` на `class="[^"]*\b(debug|draft|temp|todo|test-)`, `console.log(` в инлайн-скриптах `raw.html`, `data-debug` — норма: нет — ложные: класс `test-` у A/B-теста — норма. Видимые пометки в интерфейсе — `ux`.

**[stability-31] Ресурсы с тестовых и локальных адресов** — Grep `page.json` `"scripts"`, `"styles"` (`host`), `errors.json → failed[]`, Grep `raw.html` на `localhost`, `127.0.0.1`, `\.local\b`, `staging\.`, `dev\.`, `test\.` — норма: 0 — ложные: ссылка в тексте статьи «пример localhost» — не ресурс.

**[stability-32] Хвосты удалённой функции** — скрипт ищет элементы, которых нет (исключение `Cannot read properties of null` с селектором), ссылки на `/api/…` с 404 в `errors.json → http_errors[]`, обработчики формы, которой нет — норма: 0 — ложные: виджет, который сам проверяет наличие блока, ошибок не даёт.

**[stability-40] `zoom` на `html` или `body`** — `stability-dom.js` → `zoom.html`, `zoom.body` на 1440 и ещё раз на 1280 (`--width 1280`) — норма: `1` или `normal` — ложные: `zoom` внутри отдельного блока (иконка, превью) — не этот пункт. Масштаб страницы через `zoom` (так делают платформы на ноутбуках) расходит `getBoundingClientRect` и `offsetWidth`: попапы, подсказки и липкие блоки встают не на своё место; в Safari `zoom` работает иначе — `needs_device_check: true`. Код платформы — P3 «платформа»; свой код — P2, если на кадре видно смещение. Вид вёрстки на ноутбуках — `mobile` (`mobile.json → summary.rescale_laptop`).

## E. Страницы ошибок, PWA, сравнение

**[stability-33] Страница 404 как код** — адрес `seo.json → site.soft404[0].url` (проверочная несуществующая страница, уже в замерах); проба `probe.mjs --run "<RUN>" --url "<этот адрес>" --width 390 --shot stability-404.jpg` → `exceptions`, `console[]`, кадр — норма: без ошибок JS, без пустых вставок и полос — ложные: код ответа и soft-404 — `seo-tech`; содержание 404 — `ux`; стектрейс — `security`. Нет `seo.json` — `not_checked`: свой адрес не придумывай, служебные пути и админки не открывай.

**[stability-34] Страницы без ожидаемых элементов** — исключения на служебных страницах (политика, контакты, 404), которых нет на главной (`Cannot read properties of null`, `is not a function`), — `errors.json` по этим pid — норма: общие скрипты не падают там, где их блока нет — ложные: нет.

**[stability-35] Service worker** — `privacy.json → summary.service_workers`, `items[].storage.service_workers`, `cache_storage`; проба `stability-sw.js` → `registrations[]` (`scope`, `script`, `state`, `waiting`), `caches[]`, `this_page_cached`, `html_like_cached[]`; код SW — проба `stability-sw-code.js` по адресу `registrations[].script` (свой файл сайта, одна загрузка) → `skip_waiting`, `caches_html`, `cache_first` — норма: SW обновляется (`skipWaiting` или версия кэша в имени), HTML отдаёт из сети — ложные: SW платформы (push-уведомления) без кэша страниц — норма. SW, который кладёт HTML в кэш (`html_like_cached` не пуст, `caches_html: true`) и отдаёт его первым (`cache_first: true`, без `network_first`), — частая причина «после выкладки у посетителей старая версия» (P2). `waiting: true` — новая версия SW ждёт, пока закроют все вкладки. Где сайт регистрирует SW — `probe --grep-scripts "serviceWorker.register"`; сам файл SW эта проба не видит (он работает в отдельном потоке), поэтому его код — только через `stability-sw-code.js`.

**[stability-36] manifest при наличии SW** — `seo.json → site.icons.manifest` (`status`, `valid_json`, `name`, `start_url`, `display`, `icon_192`, `icon_512`); нет `seo.json` — `probe.mjs --run "<RUN>" --url "<href из link rel=manifest>" --width 1440 --expr "document.body.innerText.slice(0, 3000)" --no-shot` (свой файл сайта; текст JSON в `result`) — норма: при SW есть `name`, иконки 192 и 512, `start_url` — ложные: без SW manifest — пункт `seo-tech` (файлы иконок), здесь не проверяется.

**[stability-37] Сравнение с прошлым прогоном** — `state.json → flags.prev_run` → `<прошлый RUN>/snapshot/errors.json` (нет — Grep по его `page.json`; только чтение) — норма: новые ошибки отделены от старых — ложные: прошлый прогон с другими страницами (pid не совпадают) — сравнивай по `url`.

**[stability-38] Сайт на платформе: ошибки самой платформы** — `brief.platform.name`, свой раздел `platforms/<id>.md`, файл ошибки на домене платформы — норма: ошибки в коде платформы — одной находкой P3 «платформа»; ошибки в своём коде (свои вставки и доработки блоков) — по влиянию — ложные: свой код, вставленный в блок платформы, — это не «платформа».

## Готовые пробы (probe-js)

Готовые замеры лежат в плагине, копировать их не нужно: `--js` берёт файл из `<ROOT>/scripts/probe-js/` как есть. Свою пробу пиши Write-ом в `<RUN>/probe-js/`. Запуск: `node "<ROOT>/scripts/probe.mjs" --run "<RUN>" --pid <pid> --width 1440 --js "<ROOT>/scripts/probe-js/<файл>" --no-shot`. Пробы читают DOM, стили и локальное хранилище браузера; сетевых запросов не делают (фоновые запросы во время `--js` обрывает страховка). Пробы — по одной, не в фоне.

### stability-dom.js — head, hidden, дубли, двойные скрипты, zoom

`dead_anchors` — ссылки `#…` без цели на этой странице: строка в `for_other_lenses` → `ux`.

### stability-who-styles.js — какие правила CSS действуют на элемент

Селектор элемента — `--js-args '{"target":"header nav a"}'` (без него берётся `header nav a`).

Стили с чужого домена браузер не отдаёт (`cross_origin_sheets`) — их правила не видны.

### stability-forms.js — как уйдёт форма без скрипта

Запуск дважды на странице с формой заявки, на 390: как есть и с `--block "*/<основной-файл>.js"`. Ничего не нажимает и не отправляет.

Читать так: «как есть» — `submit_buttons: 0`, `required: 2` (скрипт сделал кнопку `type=button` и пометил поля); «без скрипта» — `submit_buttons: 1`, `required: 0`, `action: "/send.php"` → без скрипта форма уйдёт пустой (stability-39). `method: "get"` с контактными полями — данные в адресе: `for_other_lenses` → `privacy`.

### stability-sw.js — регистрации service worker и что лежит в кэше

`registrations` пусто, а `privacy.json` SW нашёл — запиши «проба не увидела регистрацию», выводов о SW не делай. Браузер пробы — новый профиль: кэш заполнен установкой SW в этой же загрузке.

### stability-sw-code.js — что делает код service worker

Запуск по адресу файла SW из `registrations[].script` (только свой домен): `node "<ROOT>/scripts/probe.mjs" --run "<RUN>" --url "<адрес sw.js>" --width 1440 --js "<ROOT>/scripts/probe-js/stability-sw-code.js" --no-shot`. Браузер показывает файл как текст, проба его читает.

`bytes: 0` — файл не открылся (код ответа в `status`): выводов о коде не делай. Код SW, собранный сборщиком в один файл, `workbox: true` — стратегии смотри по `network_first` и `cache_first` вместе.

### Подмена для проверки правки

- `[hidden]`: файл `<RUN>/probe-js/stability-hidden.css` с `[hidden]{display:none!important}` → `probe.mjs --pid <pid> --width 390 --css "<RUN>/probe-js/stability-hidden.css" --shot stability-hidden-fix.jpg` → кадр до и после.
- Ошибка во встроенном скрипте: исправленный скрипт в `<RUN>/probe-js/stability-fix.html` → `--inject-html "<RUN>/probe-js/stability-fix.html" --at "<селектор скрипта>" --place replace`, затем `--tap` по функции → `exceptions` пусто, `console[]` без ошибок с `phase: "interact"`, функция работает (кадр). Подмена по селектору задерживает ответ: для проверки ошибок это не важно, для замеров скорости такой способ не годится.

## Что владелец заметит руками

- На телефоне меню открывается и сразу закрывается, или не открывается со второго раза.
- Калькулятор показывает «NaN» после ввода дробного числа.
- В заявках нет телефона или имени, хотя поля обязательные: форма ушла без проверки.
- После выкладки у части посетителей старая версия сайта ещё неделю (service worker, кэш).
- Виджет отзывов или онлайн-записи — пустая рамка.
- На 404 съехала шапка или висит полоса.
- В исходном коде страницы виден комментарий с именем дизайнера или путём «C:\Users\…\макет».
- С включённым блокировщиком рекламы не работает форма или кнопка «Позвонить».
