# Чек-лист линзы `seo-tech` — техническое SEO

**Кто читает:** агент `seo-tech` (или `group` с этой линзой), скептик «замеры», критик.
**Зона:** видит ли поисковик сайт и какие адреса он берёт в индекс: коды, редиректы и зеркала, canonical, robots.txt, sitemap, meta robots, soft-404, отдача без JS и ботам, title/description/H1 как теги (есть, один, длина, дубли), лестница заголовков, JSON-LD как синтаксис, битые ссылки и сироты, картинки для поиска, адреса, иконки, подтверждения кабинетов, тестовые стенды в индексе, фасеты и пагинация, «к запуску» на бете, редиректы со старых адресов при переезде. Смысл title и description, интент, пробелы, соцпревью, GEO — `seo-content`; hreflang при запущенной `i18n` — её; товарная разметка при запущенной `ecommerce` — её.
**Справочники:** `markets/ru.md` §1 и §5 (нормы Яндекса и Google раздельно, поправки к seo-audit), `markets/intl.md` §1, `platforms/<платформа>.md` (что правится где).
**Главный замер:** `measure/seo.json` (`items[]` по страницам, `site` по сайту, `flags[]` с кодами, `norms`, `stage`, `human_checks`), `measure/links.json`; дополнительно `measure/domain.json`, `measure/forms.json`, `page.json → parity`, `pages.json`. Нет файла, на котором держится пункт (в quick нет `domain.json` и `forms.json`; скрипт упал), — пункт в `not_checked` с именем файла; «нет X» без замера не писать.

Формат пункта: **[seo-tech-NN] что проверить** — как проверить — норма — ложное срабатывание. Нет последней части — типовых ложных срабатываний не знаем.
Стадия `beta` или `prototype` (`seo.json → stage`, `brief.stage`): noindex, `Disallow: /`, canonical на стенд и 200 на несуществующие адреса — не находки; вместо них пункт seo-tech-57.

## A. Индексация и коды

- **[seo-tech-01] Выбранные страницы отдают 200 без редиректов** — `items[].fetch` (`status`, `redirects`, `chain`), флаги `status-not-200`, `redirect-chain` — адрес из меню и sitemap отдаёт 200 сразу; цепочка из 2+ редиректов — P2; 4xx/5xx у страницы из меню — P0 — 403 и капча от защиты (`fetch.antibot`) — вопрос доступа, не SEO.
- **[seo-tech-02] noindex там, где страница должна быть в поиске** — `items[].robots` (`noindex`, `meta`, `x_robots_tag`, `yandex`, `googlebot`, `noindex_by` — `all`, `yandex`, `google`: кому закрыта страница), флаги `noindex`, `noindex-yandex-only`, `noindex-google-only` (закрыто только для одного поисковика) — главная, услуги, каталог, статьи открыты; noindex на главной или посадочной — P0; закрыто только для одного поисковика из `brief.market.search_engines` — та же важность, в `norm` — какой поисковик теряет страницу — /thanks, /404, поиск, корзина, личный кабинет, бета. Обратный случай — `forms.json → items[]` с `lens: "seo-tech"`, код `thanks-indexable`: страница «спасибо» открыта для индекса — P3.
- **[seo-tech-03] noindex появляется только после JS** — `robots.noindex_only_in_js`, флаг `noindex-js` — робот без JS видит страницу открытой, с JS — закрытой: поведение непредсказуемо — P2.
- **[seo-tech-04] noindex за Disallow** — флаг `noindex-behind-disallow` — робот не прочитает noindex; Яндекс может оставить страницу в поиске (`markets/ru.md` §1) — P2, если страницу надо убрать из поиска — служебная страница в Disallow без noindex — не проблема.
- **[seo-tech-05] robots.txt не закрывает сайт и нужные разделы** — `site.robots.disallow_all` (`*`, `yandex`, `google`), `site.robots.selected_blocked[]`, флаги `robots-disallow-all`, `robots-blocks-pages` — на живом сайте `Disallow: /` — P0; закрыт раздел из меню — P1 — бета (`launch`).
- **[seo-tech-06] robots.txt есть и это текст** — `site.robots` (`status`, `missing`, `html_instead`, `content_type`), флаг `robots-missing` — 200, `text/plain`; нет файла — P2, у сайта из 1–3 страниц P3.
- **[seo-tech-07] robots.txt не закрывает CSS, JS и картинки** — флаг `robots-blocks-resources` — Google рендерит страницу без стилей — P2 — закрытые служебные скрипты платформы, не влияющие на вёрстку.
- **[seo-tech-08] Свои параметры адресов не плодят дубли (Clean-param, Яндекс)** — `site.robots.clean_param`, `clean_param_covers`; `items[].links.tracking_params` ловит только метки (`utm_`, `yclid`, `gclid`, `fbclid`, `from`), поэтому свои параметры ищи в адресах с `?` в `links.json → items[]` (`internal: true`), в `page.json → links`, в `seo.json → items[].links.param_links` (`total`, `pagination`, `sort`, `filter`, `other`, `samples`; флаг `param-links`) и в sitemap (`site.sitemap.with_params`, флаг `sitemap-params`) — метки `utm_*`, `ysclid`, `yrclid` Яндекс может чистить сам; находка — свои параметры (`ref`, `?sort=` из каталога, пагинация, фильтры CMS) в ссылках или sitemap без Clean-param и без canonical на чистый адрес — P2 — флаг `robots-no-clean-param` сам по себе не находка (`markets/ru.md` §1).
- **[seo-tech-09] Строка Sitemap в robots.txt** — флаг `robots-no-sitemap`, `site.robots.sitemaps` — P3 — sitemap по умолчанию `/sitemap.xml` найден — тоже P3.

## B. Sitemap

- **[seo-tech-10] sitemap есть и это XML** — `site.sitemap` (`missing`, `default_status`, `first.root`, `first.html_instead`, `too_big`), флаги `sitemap-missing`, `sitemap-html` (отдаёт HTML вместо XML), `sitemap-too-big` (файл больше 50 000 адресов — предел протокола) — в файле `<urlset>` или `<sitemapindex>`; нет sitemap у сайта больше 10 страниц — P2, у маленького — P3; HTML вместо XML и файл сверх предела — P2.
- **[seo-tech-11] В sitemap только живые индексируемые адреса** — `site.sitemap.sample`, `sample_bad`, флаги `sitemap-bad-urls`, `sitemap-noindex`, `sitemap-foreign` (`foreign_host_or_protocol`) — 200 без редиректа, без noindex, свой хост и протокол — P2 — проверена выборка (`seo.mjs --sitemap-sample`, по умолчанию 30 адресов), не весь файл: писать «N из M проверенных».
- **[seo-tech-12] Выбранные страницы есть в sitemap** — `site.sitemap.selected_missing`, флаг `sitemap-missing-pages` — индексируемая посадочная из меню есть в sitemap — P2 — служебные и закрытые страницы там быть не должны.
- **[seo-tech-13] lastmod честный** — `site.sitemap.lastmod` (`most_common.share`, `future`), флаги `sitemap-lastmod-same`, `sitemap-lastmod-future` — одинаковая дата у 90 %+ адресов или дата в будущем — P3 — сайт из нескольких страниц, обновлённых в один день.
- **[seo-tech-14] Число адресов sitemap похоже на правду** — `site.sitemap.urls_total` против `pages.json → discovered`, `by_template` — расхождение в разы (черновики, теги, вложения в sitemap; или половины страниц нет) — P2, `confidence: medium` — большой каталог: оценка по шаблонам.

## C. Зеркала и варианты адресов

- **[seo-tech-15] http → https одним 301** — `site.http_to_https` (`status`, `permanent`, `hops`, `final_https`), флаги `http-no-https-redirect`, `http-redirect-weak`, `no-https` — нет редиректа — P1; 302 или цепочка — P2 — HSTS и сертификат — `security`.
- **[seo-tech-16] www и без www склеены** — `site.www` (`resolves`, `status`, `to_main`, `permanent`, `canonical_to_main`), флаги `www-duplicate`, `www-redirect-temp` — второй вариант отвечает 301 на основной; два зеркала с 200 без canonical — P1 — www не резолвится (`resolves: false`) — не дубль; это `domain.json → www-no-dns`.
- **[seo-tech-17] Слэш, `/index.html`, регистр** — `site.url_variants[]` (`kind`: `slash`, `case`, `index_html`, `index_php`; `platform_alias` — пункт seo-tech-18; `status`, `final_status`, `permanent`, `canonical_to_original`, `duplicate`), флаги `duplicate-<kind>` (`duplicate-slash`, `duplicate-case`, `duplicate-index_html`, `duplicate-index_php`) — вариант отвечает 301 или отдаёт canonical на основной; 200 без того и другого — P2 — 404 на варианте — норма.
- **[seo-tech-18] Алиасы платформы** — `site.url_variants[]` с `kind: "platform_alias"` (адрес вида `/page123.html` для страницы с чистым адресом), флаг `duplicate-platform_alias`; другие служебные адреса конструктора — в `pages.json → not_selected_sample`, sitemap, ссылках — 301 или 200 с canonical на чистый адрес — P2 — особенности платформы, которые не правятся (`platforms/*.md`), — P3 с пометкой «платформа».

## D. canonical

- **[seo-tech-19] canonical есть на индексируемых** — `items[].canonical.count`, флаг `canonical-missing` — P2 при дублях адресов (C), P3 на маленьком сайте без вариантов — бета.
- **[seo-tech-20] canonical на себя, абсолютный, без параметров** — `canonical.self`, `exact_self`, `absolute`, `has_params`, `protocol_mismatch`, `host_mismatch`; флаги `canonical-other`, `canonical-relative`, `canonical-protocol-host` — на другую страницу: P0 для страницы каталога или раздела, которая должна быть в поиске; canonical всех карточек ведёт на список — P1 (`severity.md` §5); остальные — P1 — пагинация с canonical на первую страницу — тоже находка (seo-tech-52).
- **[seo-tech-21] Один canonical в head, скрипт его не меняет** — `canonical.distinct`, `in_body`, `differs_raw_dom`, `raw_abs`; флаги `canonical-multiple`, `canonical-js-changed` — P1.
- **[seo-tech-22] Стенд не протёк в боевую сборку** — canonical, og:url, sitemap или ссылки на тестовый домен (`host_mismatch`, `og.url_not_canonical`) — на живом сайте P0 — бета.

## E. Ошибки и ссылки

- **[seo-tech-23] Случайный адрес отдаёт настоящий 404** — `site.soft404[]` (`status`, `verdict`, `says_not_found`, `same_as_home`, `kind`), флаг `soft-404` — 200 на несуществующий адрес — P1: мусор и дубли в индексе — бета; SPA, где 404 рисует скрипт, — тоже находка.
- **[seo-tech-24] Страница 404 своя** — флаг `404-bare`, `own_template`, `internal_links` — P3 — как страница помогает посетителю — `ux`, текст — `copy`.
- **[seo-tech-25] Битые внутренние ссылки** — `links.json → items[]` (`internal`, `status`, `state`, `reason`, `from[]` с `pid` и `region`), `summary.broken_internal`, флаг `broken-internal-links`; битая — только `state: "broken"` (в том числе `reason: "soft404"`), по `ok: false` не отбирать — из меню и с главной P1, из текста P2 — `state` `blocked`, `auth`, `skipped` и флаг `links-blocked` (защита, соцсети: 401/403/418/429/999, челлендж) — не битые: перечень в `not_checked`; `unreachable`, `unclear`, `not_checked` — перепроверить `probe --url` или `not_checked`.
- **[seo-tech-26] Битые внешние ссылки** — `summary.broken_external`, флаг `broken-external-links`, у ссылки `state: "broken"` (правила `state` — seo-tech-25) — P3; на документы, оплату, карту — P2 — внешний сайт режет роботов (403) — перепроверить `probe --url`, иначе не находка.
- **[seo-tech-27] Ссылки без начального «/»** — `items[].links.relative_no_slash`, флаг `relative-links` — относительный адрес на вложенной странице ведёт на 404 с кодом 200 — P2 — `../` намеренно в статике.
- **[seo-tech-28] Внутренние ссылки с метками** — `items[].links.tracking_params` (только метки `utm_`, `yclid`, `gclid`, `fbclid`, `from`; свои параметры — пункт seo-tech-08), флаг `internal-utm` — плодят дубли и портят аналитику — P2.
- **[seo-tech-29] Якоря на несуществующие id** — `items[].links.broken_anchors`, флаг `broken-anchors` — P3 — переходы по якорям для посетителя — `ux`.

## F. Отдача без JS и роботам

- **[seo-tech-30] Главное есть в исходном HTML** — `items[].h1.raw_count`, `items[].text.raw_len` против `dom_len`, `text.js_only`, `links.raw_internal`; флаги `h1-js-only`, `js-only-content`; сверить глазами `snapshot/<pid>/raw.html` — H1, текст и ссылки есть без JS; пустой `<div id="root">` — P0–P1 для сайта, которому нужен поиск — перед P0 открыть `raw.html`: малый текст в ответе бывает у страниц с переводами в JS и у визиток; разница в длине без потери H1 и ссылок — P3. Флаг `js-added-content` (`text.js_added`: часть текста добавляет JS, основной есть в HTML) — норма, не находка. Флаг `title-js-changed` (`title.changed_by_js`: title в исходном HTML и после JS разный, робот без JS видит первый) — P3; в исходном HTML title пустой или шаблонный — P2.
- **[seo-tech-31] JSON-LD и noindex появляются только после JS** — `jsonld.only_in_js`, `robots.noindex_only_in_js`; флаги `jsonld-js-only`, `noindex-js` — P2.
- **[seo-tech-32] Ответ роботам равен ответу браузеру** — `site.bots.bots[]` (`bot`, `status`, `verdict`, `diff`, `links_jaccard`, `text_len_delta_pct`), флаг `bot-differs` — `same`; `differs` — P1 (клоакинг или защита режет контент) — `bot_ua_blocked` — не находка: строка в `not_checked` с проверкой из `human-checks.md` (Вебмастер «Проверка ответа сервера»); `blocked_for_all` — защита режет всех, вопрос владельцу и `stability`; `no_baseline`, `parse_error`, `error` — не с чем сравнить, `not_checked`; `site.bots` нет (quick, seo.mjs без `--as-bot`) — `not_checked`.
- **[seo-tech-33] Спам для ботов и взлом** — `site.bots.bots[].spam_only_for_bot`, `items[].spam`, флаг `spam-words` (казино, ставки, займы, виагра) — P0 и строка `security` — слова из тематики сайта (сайт букмекера).
- **[seo-tech-34] Мобильная отдача не беднее десктопной** — `page.json → parity` (`title_same`, `h1_same`, `text_ratio`, `headings_shown`) — текст и ссылки на 390 px не меньше 80 % от 1440 — P2 — блоки, скрытые на телефоне стилем, но присутствующие в HTML.

## G. title, description, H1 как теги

- **[seo-tech-35] title есть, один, уникален** — `items[].title` (`len`, `count`), флаги `title-missing`, `title-multiple`; `site.title_duplicates` — нет title — P1; одинаковый у разных страниц — P2, у главной и посадочных — P1 — пагинация и фильтры с одинаковым title при canonical — не дубль.
- **[seo-tech-36] Длина title по обеим нормам** — `title.len`, `title.norms.yandex` и `.google`, `seo.json → norms.title`, флаги `title-length-yandex`, `title-length-google` — рабочие нормы: Яндекс 30–70, Google 50–60 (`markets/ru.md` §1); вне нормы P3; обрезан оффер или главный запрос — P2 — формулировка и запрос — `seo-content`; находку по длине одну на сайт (`sitewide`).
- **[seo-tech-37] description есть, уникален, по нормам** — `description` (`count`, `empty`, `len`, `norms`), `site.description_duplicates`, флаги `description-missing`, `description-length-*`; `og.desc_differs` — пустой на большинстве страниц — P2 одной находкой; длина вне норм P3 — Яндекс 120–170 (до 250), Google 150–160; текст description — `seo-content`.
- **[seo-tech-38] Ровно один видимый H1** — `h1.count`, `visible_count_hint`, `logo_like`, `hidden_hint`; флаги `h1-missing`, `h1-multiple`, `h1-logo` — нет H1 на посадочной P1, два и больше P2, логотип в H1 P3 — H1 в скрытом мобильном дубле платформы (`hidden_hint`) — проверить кадром.
- **[seo-tech-39] Лестница заголовков** — `headings` (`skips`, `h3_before_h2`, `cta_like`, `empty`, `outline`), флаги `headings-skip`, `headings-cta` — без скачков по порядку DOM, кнопки и плашки не размечены заголовками — P3; H3 карточек раньше H2 секции на посадочной — P2 — пустые и скрытые заголовки, чтение скринридером — `a11y`.
- **[seo-tech-40] Предлагаемые title, description, H1** — если находка требует нового текста: длина по обеим нормам, ключ в естественной форме в начале, бренд в конце, без набора фраз, без выдуманных фактов; `node "<ROOT>/scripts/textscan.mjs" --text '<after>'` → 0 (строка в одинарных кавычках, без цитат сайта в «…» и без `'`, `"`, `` ` ``, `$`, `\`; `agents/seo-tech.md`, шаг 9) — смысл и запрос — `seo-content`, готовые тексты пишет он; у seo-tech — только когда тег пуст.

## H. Разметка JSON-LD

- **[seo-tech-41] JSON-LD разбирается** — `items[].jsonld` (`blocks`, `raw_blocks`, `parse_errors`), флаг `jsonld-parse-error` — один сломанный блок выключает весь блок — P1.
- **[seo-tech-42] Обязательные поля типов** — `jsonld.types`, `jsonld.issues[]` (`type`, `field`, `level`, `engines` — по справке какого поисковика), флаг `jsonld-fields-missing` (только `level: "required"`; `recommended` — данные, находка не больше P3): Organization и LocalBusiness (name, address, telephone в формате +7…, openingHours, geo — широта и долгота не перепутаны), Product без `offers.price`, aggregateRating без отзывов на странице, BreadcrumbList (последний пункт = адрес страницы), BlogPosting (author, datePublished, image), Event = видимый анонс — P2 — тип, которого поисковик не показывает (FAQ-сниппеты Google не показываются с 07.05.2026), — не повод добавлять разметку; флаг `jsonld-faq-retired` — справка: не находка, совета «добавить FAQ» нет, верную разметку FAQPage удалять не нужно.
- **[seo-tech-43] Разметка совпадает с видимым** — `jsonld.mismatches`, флаг `jsonld-mismatch`: FAQPage ≠ видимый FAQ, цена, телефон, адрес, рейтинг в разметке ≠ на странице — P1: разметка врёт — расхождение самих фактов по сайту ведёт `facts` (таблица), у seo-tech — что разметка не равна странице.
- **[seo-tech-44] Шаблон не раздаёт чужую разметку** — BreadcrumbList и `@id` одинаковы на страницах разных разделов («Главная → Блог» на карточках товаров) — сравнить `jsonld` страниц одного шаблона — P2.
- **[seo-tech-45] Самоприсвоенный рейтинг и фальшивые даты в разметке** — флаг `jsonld-self-rating`, поле `jsonld.self_rating[]` (`type`, `field`, `reviewed` — рейтинг или отзывы организации о себе: Google такие звёзды не показывает), aggregateRating без отзывов на странице, `dateModified` = дате прогона на всех страницах — P2, `needs_decision`.

## I. Картинки, адреса, иконки

- **[seo-tech-46] Смысловые картинки с alt для поиска картинок** — `items[].images` (`no_alt`, `empty_alt`, `junk_alt`, `samples_no_alt`), флаги `alt-missing`, `alt-junk` — P2 для каталога и портфолио, иначе P3; совет «ключи в alt» не давать — alt описывает картинку — alt как доступность — `a11y`; декоративные с пустым alt — норма.
- **[seo-tech-47] Адреса латиницей, строчными, через дефис** — `items[].url_format` (`cyrillic`, `uppercase`, `underscore`, `double_slash`, `extension`), флаг `url-format` — P3; заглавные или кириллица, у которых второй вариант отдаёт 404 или дубль, — P2 — менять адреса живого сайта без 301 — вредно: правка только с 301.
- **[seo-tech-48] Иконки для выдачи** — `site.icons` (`favicon_ico`, `has_svg`, `has_png_32_or_more`, `apple_touch`, `manifest`, `norms` — `yandex`/`google`: `ok`, `small`, `svg_only`, `missing`; `best_square_px`, `yandex_redirect`, `source` с датой сверки), флаги `favicon-missing`, `favicon-ico-missing`, `apple-touch-missing`, `apple-touch-small`, `manifest-missing`, `favicon-yandex-norm` (нет SVG и нет 120×120), `favicon-google-norm` (мелкая или только SVG), `favicon-redirect` (фавикон через редирект — Вебмастер считает ошибкой) — нет иконки вообще — P2; остальное P3 — как иконка читается в 16–32 px — `visual`.
- **[seo-tech-49] Устаревшие и полезные мета** — флаг `meta-keywords` (убрать, P3); `robots.max_image_preview` (`large` для сайтов, где картинки приводят трафик, P3).

## J. Сайт целиком

- **[seo-tech-50] Подтверждения кабинетов и счётчики** — `site.verification` (`yandex`, `google`), флаг `verification-missing`, `forms.json → summary.counters`; без `forms.json` (quick) счётчики ищи в `raw.html` и `dom.html` главной: `mc.yandex.ru`, `ym(`, `gtag(`, `googletagmanager.com`, `GTM-`, `top-fwz1.mail.ru`; не нашёл и файла нет — «счётчики не проверялись» в `not_checked` — нет meta-подтверждений и счётчиков: вопрос в `open_questions` «есть ли доступ к Вебмастеру и Search Console»; P1 «индексацию проверить нечем» с `owner: "решение владельца"` — только если владелец ответил, что доступа нет: `brief.access.*: false` при `brief.source.access: "user"` или запись в `owner_decisions`; `access: {false…}` без этой пометки — умолчание `init-run`, не ответ: только вопрос в `open_questions`, без P1; и сайту нужен поиск (`markets/ru.md` §1, «Как применять») — подтверждение файлом, DNS, через Метрику или Яндекс Бизнес в HTML не видно: писать «в коде страниц не найдено».
- **[seo-tech-51] Сироты по основному содержимому** — `site.orphans`, `site.inbound[pid]` (`main`, `nav`), флаг `orphans-main`, `links-blocks.json → summary.selected_not_linked_from_selected` — посадочная получает ссылки из текста других страниц; ссылки только из подвала или меню — P2 — служебные страницы.
- **[seo-tech-52] Фасеты и пагинация (каталог, блог)** — адреса с `?` в `links.json`, `pages.json → by_template`, canonical страниц пагинации — фильтры не плодят индексируемые дубли (canonical, noindex, Clean-param), полезные посадочные фильтры открыты; пагинация с canonical на себя; `rel=prev/next` не нужен — сотни дублей — P1 — при запущенной `ecommerce` разметка товаров — её.
- **[seo-tech-53] Тестовые стенды в индексе** — `domain.json → flags[]` с кодом `test-stand-open`, `domain.json → subdomains`; нет `domain.json` (quick) — `not_checked` — стенд закрыт паролем, noindex или `Disallow`; открытый стенд, повторяющий сайт, — P1 — что стенд доступен снаружи и висящие CNAME — `security`.
- **[seo-tech-54] llms.txt и ИИ-боты как техника** — `site.llms` (код, `present`, `html_instead`), `site.robots.ai_bots[]` (`bot`, `operator`, `purpose` — `training`, `search`, `user`; `obeys_robots`, `explicit`, `root_allowed`), `site.robots.yandex_ai`, `site.robots.content_signal` — нет llms.txt — не находка; закрыт бот обучения (`purpose: "training"`) — выбор владельца, не находка; закрыт поисковый ИИ-бот (`purpose: "search"`) — сайт не попадёт в ответы этого ИИ-поиска, вопрос в `open_questions`; бот с `obeys_robots: false` (заходит по просьбе пользователя) robots.txt не читает — запрет для него ничего не даёт, не находка; файл отдаёт HTML вместо текста — P3; ИИ-боты закрыты вопреки брифу — вопрос в `open_questions` — содержимое llms.txt — `seo-content`, факты в нём — `facts`.
- **[seo-tech-55] IndexNow и HTML-карта** — большой сайт (сотни страниц) без HTML-карты и без IndexNow (Яндекс, Bing) — P3, вопрос владельцу — Google IndexNow не поддерживает.
- **[seo-tech-56] hreflang (если `i18n` не запущена)** — три источника: `items[].hreflang[]` (`<head>`: `lang`, `href`, `valid`, `suggest`), `items[].hreflang_header` (заголовок `Link`), sitemap (`site.sitemap.hreflang`: `used`, `checked_file`, `first_file_only`); `site.hreflang.sources_checked`, `site.hreflang.pages[]` (`sources`, `issues`: `no_self`, `no_x_default`, `bad_code:`, `wrong_code:`, `target_<код>:`, `no_return:`, `conflict:<язык>` — источники дают разные адреса для одного языка, `duplicate:<источник>:<коды>`), флаг `hreflang-issues` — взаимные ссылки, x-default, коды ISO, цели 200 — P1 за невзаимность и неверный код; `conflict:` — P3 (i18n-09); sitemap проверен только первый файл (`first_file_only: true`) — остальные файлы в `not_checked` — при запущенной `i18n` — её пункт.

## K. Стадия и переезд

- **[seo-tech-57] Бета и прототип: чек-лист «к запуску»** — `brief.stage`, `seo.json → stage`, `pages.json → beta_signals` — одна находка с тегом `launch` и списком: снять noindex и `Disallow: /`; canonical, og:url и sitemap на боевой домен; 301 со старых адресов; подтвердить Вебмастер и Search Console; счётчик; robots.txt с Sitemap — важность по влиянию на запуск (P1) — сами noindex и Disallow на бете — не находки.
- **[seo-tech-58] Переезд или редизайн: старые адреса ведут на аналоги** — `brief.baseline` (или `state.json → flags.baseline`): 10–15 старых адресов разных шаблонов — сначала из `<RUN>/baseline/pages.json` (`selected[]`, `discovered`, `by_template`), если конвейер снял старый сайт; иначе из `<baseline>/sitemap.xml` (`probe --url "<baseline>/sitemap.xml" --no-shot --js "<RUN>/probe-js/seo-tech-locs.js"`; файл скрипта — в `agents/seo-tech.md`, шаг 6; в файле есть `<sitemapindex>` (`index: true`) или все `locs` кончаются на `.xml` — открыть 1–2 вложенных sitemap), затем по каждому `probe --url "<старый адрес>" --no-shot` → `status`, `final_url`, `chain` — куда ведёт: каждый старый адрес приводит на свой аналог; 404 или главная вместо аналога у важной страницы — P0 к дню переезда; тип редиректа — по `chain` (`redirect`: `http`, `js`, `other`): первый шаг 301 или 308 по `http`, дальше сразу аналог с 200 — норма; 302, 307, цепочка — P2; шаг `js` или `other` (скрипт, meta refresh) — P2: поисковик может его не учесть; `chain` нет в сводке ответа — Read файла `file_abs` — старый сайт уже не отвечает или probe отказал (чужой хост) — `not_checked` и вопрос владельцу.

## Методика seo-audit (пересказ) и поправки

Навык `marketing:seo-audit` (Anthropic, Apache 2.0) даёт каркас аудита. Ревизор берёт из него порядок и форму, нормы — свои. Вызов — тип `Technical SEO check` с адресом, рынком и пометкой «доступов к Ahrefs и Search Console нет» в аргументах (`agents/seo-tech.md`, раздел 8); в экономном режиме навык не вызывается.
- **Технический чек-лист навыка** (скорость, мобильная версия, разметка, обход, битые ссылки, HTTPS, Core Web Vitals, индексация и дубли) → разделы A–J выше; скорость и мобильная вёрстка — линзы `perf` и `mobile`.
- **Статусы навыка Pass / Fail / Warning** → `clean_checks` (Pass с цифрой), находка (Fail), находка P3 или `open_questions` (Warning).
- **Шкала навыка** Critical / High / Medium / Low → P0 / P1 / P2 / P3 (`severity.md` §8): закрыто от индекса, дубли, 404 у важных — P0; title, H1, canonical — P1; разметка, alt — P2; адреса, мелочи — P3.
- **«Быстрые победы на неделю» и «стратегия на квартал»** → `effort: "S"` у P1–P2 без решения владельца попадает в быстрые победы отчёта; стратегию пишет `strategist`.
- **Поправки (`markets/ru.md` §5):** нормы навыка гугловые — рядом писать нормы Яндекса; FID заменён INP; «ключи в alt» не советовать; добавить Clean-param для своих параметров, Вебмастер, регион, IndexNow, hreflang, фасеты, llms.txt; FAQ-сниппеты Google не показываются с 07.05.2026; финальный вопрос навыка «Хотите, я…» игнорировать; Ahrefs и Semrush нет — данные только из замеров и от владельца.

## Что владелец заметит руками

1. В Вебмастере или Search Console в «Исключённых» — адреса с метками и параметрами.
2. Сайт открывается и с www, и без, и по http — три «разных» сайта.
3. Страница услуги не находится по своему названию: на ней noindex или canonical на главную.
4. Несуществующий адрес показывает главную вместо «страница не найдена».
5. В выдаче нет иконки сайта или у всех страниц один заголовок.
6. Старые адреса после переезда ведут на 404.
7. В исходном коде (Ctrl+U) нет текста страницы — только пустой контейнер.
