# Чек-лист главного редактора

Процедура для `revizor:editor`. Редактор сводит находки в отчёт: решает слияния и формулировки, пишет «главное» и первые действия, собирает отчёт скриптом, смотрит **все** куски готового отчёта и правит, пока самопроверка не пройдёт. Числа, номера, порядок и сверку «ничего не потеряно» делают скрипты; редактор пишет только решения (`report/editorial.json`) и верх отчёта (`report/summary.json`).

Главное правило — **не смягчать**: важность меняется только через вердикты, подтверждённое уходит только слиянием, сомнений и похвалы в тексте нет. Структура отчёта — `report-structure.md`, тон и запрет-лист — `tone.md`.

## 1. Режимы (`MODE=`)

| Режим | Что делаешь | Итог |
|---|---|---|
| `full` | всё ниже | `report/report.html`, `registry.xlsx` (+ PDF) |
| `quick` | то же короче: суть 3 вывода, первые действия до 5, без стратегий и оценок | то же |
| `health` | находок линз нет; суть — по `report/diff.json` и замерам здоровья | то же |
| `rivals` | сборка галереи конкурентов, просмотр кадров, правка формулировок идей | `report/rivals.html`, `rivals.xlsx` |
| `recheck` | сборка итога перепроверки, просмотр кадров | `report/recheck.html` |

## 2. Сбор (full, quick)

- **[editor-01]** `node "<ROOT>/scripts/merge.mjs" --run "<RUN>" --audience <audience>` — первым шагом всегда, даже если `report/digest.md` уже лежит: после второго круга, скептика второго круга и критика старый свод неполон. Merge даёт свежие `report/candidates.json`, `digest.md`, `handoffs.json`; он читает файлы линз, вердикты скептиков и поправки критика, сам ничего не решай за них.
- **[editor-02]** Прочитай `report/digest.md` целиком (строка на находку). Полные находки — `node "<ROOT>/scripts/show.mjs" --run "<RUN>" --ids a,b` или `--cluster cNN`, `--lens x --severity P0,P1`, `--verdict adjusted`, `--rejected`. Знаки расшифрованы в шапке digest. Главные: в столбце вердикта `*` — требует проверки (P0–P1 без вердикта или вердикты скептиков спорят), `⚡` — два скептика разошлись, `~` — скептик снял текст «стало», `!` — скептик забраковал правку, `?` — ошибка схемы, `(+скептик)` — находку добавил скептик; в столбце важности `↑` — повышено критиком, `↓` — понижено скептиком, `↑?P1` — критик хотел P1, но находка не проверена.
- **[editor-03]** Прочитай `report/handoffs.json` (`questions`, `strengths`, `wrong_strengths`, `not_checked`), `critic/round-*.json` (`contradictions`, `weak_wording`, `owner_would_notice`, `gaps`), `critic/strategy.json → open_questions` (если были стратегии), `brief.json` (`goals_questions`, `audience`, `lang`, `owner_decisions`, `do_not_touch`, `human_checks`, `rivals_light`, `source`, `baseline`, `known_issues`), `state.json → flags` (`pdf`, `scores`, `strategy`, `profile`, `report_css`), строки `[external]` в `log.md` и разделы «Внешние запросы» в `notes/*.md` ([editor-34]).

## 3. Решения: `report/editorial.json`

```json
{ "merge": [ { "keep": "mobile-03", "absorb": ["a11y-07", "visual-11"], "title": "На 390 px таблица цен шире экрана на 34 px на 3 страницах" } ],
  "drop": [ { "id": "seo-content-09", "why": "дубль seo-tech-04" } ],
  "severity": [ { "id": "product-02", "to": "P0", "why": "на сайте нет ни одной кнопки записи в первом экране" } ],
  "rewrite": { "copy-05": { "title": "«Лучший кофе в городе» в первом экране главной без источника", "fix": "…" },
               "color-02": { "title": "Кнопка «Купить» на 390 px: контраст 3,1:1 при норме 4,5:1", "evidence": "measure/contrast.json: кнопка «Купить» на p03@390" } },
  "order_hint": ["product-02", "mobile-03"], "external_drop": [] }
```

**Слияние (`merge`)**
- **[editor-04]** Одна причина — одна находка: одинаковый селектор, шаблон или механизм на многих страницах и в разных линзах. `keep` — находка с лучшим доказательством (замер, вердикт `confirmed`, кадр); `absorb` — остальные. `title` слитой находки называет общий масштаб («на 7 страницах из 9»).
- **[editor-05]** Разные причины одного симптома (разные правки) не сливаются.
- **[editor-06]** Кластеры в `digest.md` — подсказка. Перед слиянием посмотри `show.mjs --cluster`.
- **[editor-07]** Противоречие цифр из `critic → contradictions`: оставь находку с верной цифрой (по замеру), вторую слей в неё. Подтверждённую находку удалить нельзя — только слить.

**Снятие (`drop`)**
- **[editor-08]** `drop` разрешён в двух случаях, других нет:
  - дубль: в `why` — id находки, которая остаётся: «дубль seo-tech-04»;
  - находка с ошибкой схемы (`schema_issues`, знак `?` в digest): `why` — «ошибка схемы: <поле>».

  `confirmed` и `adjusted` уходят только через `merge`. Находка кажется ложной, «мусором» или спорной — не снимай: строка оркестратору «нужна перепроверка: <id> — <почему>» и запись в `editorial.json → notes`. Число снятого — в ответ оркестратору.

**Важность (`severity`)**
- **[editor-09]** Повышать можно с доводом (`why`): нет кнопки действия, сломан главный сценарий, неверная цена, место — первый экран главной. Находку со знаком `↑?` (критик хотел повысить, а скептик её не проверял) сам не повышай: строка оркестратору «нужна проверка скептиком: <id>, критик хочет <P>».
- **[editor-10]** Понижать важность ты не можешь: `merge.mjs` уже применил `severity_after` скептика, а `finalize.mjs` откажет в понижении ниже уровня любой слитой находки. Откатить можно только своё же повышение. Повышение критика (знак `↑`, в `severity_trail` есть `by: "critic"`) необратимо. Считаешь важность завышенной — строка оркестратору с доводом; решает новый вердикт скептика.

**Тексты (`rewrite`)**: поля `title`, `problem`, `impact`, `fix`, `after`, `before`, `scenario`, `evidence`. Другие поля `finalize.mjs` не переписывает (отказ). `evidence` можно только сократить или пересказать: новая цитата или новое число в нём — отказ.
- **[editor-11]** `title` — утверждение с цифрой и местом, до 100 знаков, на 390 px не длиннее двух строк: «На 390 px кнопка „Записаться“ не нажимается: сверху прозрачный слой».
- **[editor-12]** Убери сомнения, оценки людей, нейрослоп и канцелярит (`tone.md`, раздел «Запрещено»). Перед записью прогони спорные строки: Write в `<RUN>/probe-js/editor-text.txt` (строка на строку, цитаты сайта можно оставить), затем `node "<ROOT>/scripts/textscan.mjs" --run "<RUN>" --text-file "<RUN>/probe-js/editor-text.txt"` (код 4 — переписать строки, названные в выводе).
- **[editor-13]** Поправки скептика переносишь в текст:
  - `!` (`fix_ok=false`) — перепиши `fix` по его `note`;
  - `~` (текст «стало» снят) — дай вариант из его `note` в `after` или оставь поле пустым;
  - вердикт `adjusted` с `note`, начинающимся с `evidence:` (у линзы неверная цифра или цитата), — верное значение из этой строки ставь в `title` и `problem`, а из `evidence` неверное значение убери сокращением (новое число туда `finalize.mjs` не пустит; замер скептика виден в строке «как проверено»). Список: `show.mjs --run "<RUN>" --verdict adjusted --max 100`.
- **[editor-14]** Факты не смягчай: цифра, место, норма остаются. Смягчается подача: «На странице указано…», «Предлагаем…».
- **[editor-15]** Для `external`: в `problem`, `impact`, `fix` и `evidence` нет путей к файлам, имён скриптов, кодов линз и находок, «probe», «headless», «агент», «не проверено». Пиши словами: «Мы открыли страницу на ширине 360 px: таблица цен выходит за край на 64 px». `evidence` с путями и командами переписывай через `rewrite` тем же фактом словами, без новых чисел и цитат: было «measure/contrast.json: p03@390 3,1:1, #8a8a8a на #f2f2f2» — стало «Контраст текста кнопки на телефоне — 3,1:1: серый #8a8a8a на светло-сером #f2f2f2». Самопроверка `report.mjs` ловит пути и коды (правило `forbidden`, адрес поля `<rid> evidence`); пути в обратных кавычках (`` `measure/seo.json` ``) она пропускает, но читатель их видит — ищи их и при просмотре кадров отчёта.

**Порядок и чужая команда**
- **[editor-16]** `order_hint` — внутри одной важности первыми: главное действие и форма, первый экран, сквозное на весь сайт, затем по страницам.
- **[editor-17]** `external_drop` — только для `external` и только находки с `needs_device_check: true` или `confidence: "low"` (их скрипт снимет и сам, список можно оставить пустым). Другие основания не принимаются: P2–P3 без вердикта скептика остаются в отчёте и в приложении «Мелкие правки». Проверки на устройстве перейдут в «Советы» (`summary.device_checks`).
- **[editor-17a]** После `finalize.mjs` для `external` возьми строку вывода «Снято для external: N — P0–P1 без проверки: a · проверить на устройстве: b · низкая уверенность: c» (то же — `report/external-dropped.json → counts`; находки — `items[]` с `severity` и `drop_reason`). В ответ оркестратору: «для external снято N находок (P0–P1 без проверки a, на устройстве b, низкая уверенность c), список — report/external-dropped.json». Есть снятые P0–P1 без проверки (так бывает в lite, где скептик смотрит только P0) — добавь: «до отправки отчёта стоит перезапустить скептика по: <id>».

## 4. Сверка фактов

- **[editor-18]** Возьми все P0 и до 15 случайных P1–P2. Сверь цитату и цифру с первоисточником: `snapshot/<pid>/text.md`, `measure/*.json`, кадр. Не сходится формулировка — поправь `title` и `problem` через `rewrite`. Не сходится цифра или цитата в `evidence` (новое значение `finalize.mjs` в `evidence` не пустит) или находка ложная — строка оркестратору «нужна перепроверка: <id> — <что не сходится>» и запись в `editorial.json → notes`.
- **[editor-19]** Номера `rid` (P0-01…) появляются только после `finalize.mjs`. В `summary.json` ссылайся на `rid`; в `editorial.json` — на `id` находок.

## 6. Верх отчёта: `report/summary.json`

Поля — `report-structure.md` §5. Правила:
- **[editor-22]** `verdict_line` — одно предложение: что за сайт и главное, что мешает. «Сайт кофейни продаёт кофе с собой, но с телефона заказ не оформить: меню закрыто прозрачным слоем».
- **[editor-23]** `essence` — 3–6 выводов (quick — 3), в каждом цифра и номер; первый — главное для бизнеса (где теряются заявки или деньги).
- **[editor-23a]** Переезд (`brief.baseline` есть): один вывод `essence` — итог сравнения «старое → новое» числом по таблицам из `notes/product.md` и `notes/facts.md`: «из 40 пунктов старого сайта: есть 31, иначе 5, частично 1, нет 3». Для `owner` и `team` — плюс главные «нет» с номерами. Для `external` — только пункты «иначе», «частично», «нет»; «есть» — одним числом.
- **[editor-24]** `goals_answers` — ответ на каждый вопрос владельца В1…Вn из `brief.goals_questions`, одной строкой со ссылкой на номера. Ответа нет в данных — «по снятым страницам ответа нет: …» и пункт в `owner_todo`.
- **[editor-25]** `traffic_lights` — 6–10 разделов: «Путь к заявке», «Навигация», «Дизайн», «Мобильная версия», «Доступность», «Тексты и факты», «Поиск», «Скорость», «Стабильность», «Безопасность и данные». `red` — есть P0 или 3 и больше P1; `yellow` — есть P1 или много P2; `green` — только P3 или ничего. Раздел без отработавшей линзы не ставь зелёным: пропусти его и добавь в `not_checked`.
- **[editor-26]** `top_actions` — до 10, порядок: внешнее и доступы, которые открывают остальные работы → P0 → быстрые победы → остальное. Каждое — `{ rid, action, why, who }`, `action` глаголом. `rid` обязателен (`validate.mjs` проверит, что номер есть в `findings.json`): доступ или внешнее действие без своей находки идёт в `owner_todo`, а в `top_actions` — только если его требует находка (тогда `rid` этой находки).
- **[editor-27]** `quick_wins` — до 10 номеров: трудоёмкость S, важность P1–P2, без решения владельца.
- **[editor-28]** `strengths` — до 6 из `handoffs.strengths` без попавших в `wrong_strengths`. Только то, что помогает дойти до действия, с цифрой. «Единый стиль», «аккуратно», «современно» не берутся.
- **[editor-29]** `decisions` — вкусовые находки (`taste`) и `needs_decision`: вопрос, 2–3 варианта, рекомендованный первым со ★, номера. Для `external` вкусовое — одной строкой на тему.
- **[editor-30]** `device_checks` — до 10: находки с `needs_device_check`, `brief.human_checks`, вид ошибок пустой формы (ячейки `"device"` матрицы критика). Формула: «устройство · где · что сделать · что считать проблемой · сколько времени» (`human-checks.md`). Для `external` — советом «Проверьте…».
- **[editor-31]** `owner_todo` — вопросы линз (`handoffs.questions`, без повторов) и стратегов (`critic/strategy.json → open_questions`), доступы (Метрика, Вебмастер, Search Console), факты на подтверждение. Для `external` — пусто.
- **[editor-32]** `not_checked` — owner и team: упавшие линзы, незакрытые задачи критика, страницы, которые сайт не пустил снять, главное из `handoffs.not_checked` (до 10 строк, сгруппировано). Для `external` — пусто.
- **[editor-33]** `method` — owner и team: сколько страниц и ширин, что проверяли, что не делали («формы не отправлялись»). Добавь по одной фразе, если было:
  - второй круг нашёл P0–P1 (`findings/*.r2.json`, в digest id вида `<lens>-r2-NN`) — и строку в `not_checked`: пробелы первого круга были существенные, третьего круга нет;
  - скептик отклонил находки как известные владельцу (`show.mjs --rejected`, `note` «известно владельцу») — «N находок совпали с тем, что вы уже знаете, и в отчёт не вошли»;
  - агенты ходили наружу (разделы «Внешние запросы» в `notes/*.md`) — «агенты читали первоисточники: <сервисы>, <сколько> запросов».

  Для `external` — одна фраза без «агент», «Ревизор», «не проверено».
- **[editor-34]** `external_services` — только запросы агентов, одна строка на сервис: «<сервис> · что ушло · сколько раз». Агенты наружу не ходили — `[]`.
  - Скрипты: строки `[external]` в `log.md` в `external_services` не переписываешь: раздел «Что отправлялось во внешние сервисы» `report.mjs` собирает из `log.md` сам, повтор дал бы каждый сервис дважды. Строки скриптов нужны только для фразы в `method` ([editor-33]).
  - Агенты: разделы «Внешние запросы» во всех `notes/*.md` (линзы, `notes/skeptic-*.md`, `notes/strategy-*.md`, `notes/rival-*.md`): «WebFetch · официальный портал законов · 3».
- **[editor-35]** `rivals_compared` — из `brief.rivals_light` (адрес и почему взят); `memory_applied` — сколько решений и фактов взято из памяти сайта (поля `brief.source` со значением `memory`).
- **[editor-36]** `counts` — из первой строки вывода `finalize.mjs` (или `report/findings.json → counts`); `process` — из `report/candidates.json → counts`: `found` = `total` + `rejected`, `confirmed` и `adjusted` = `by_verdict.confirmed` и `by_verdict.adjusted`, `unverified` = `by_verdict.unverified` + `by_verdict.needs_device`, `rejected` = `rejected`; `rounds` — 2, если есть `critic/round-1.json` с вердиктом «ещё круг нужен» и файлы `findings/*.r2.json`, иначе 1.
- **[editor-37]** `node "<ROOT>/scripts/validate.mjs" --file "<RUN>/report/summary.json"` — сверит номера и числа с `findings.json`. Исправь все ошибки.

## 7. Отчёт и самопроверка

- **[editor-38]** `node "<ROOT>/scripts/report.mjs" --run "<RUN>" --audience <audience> --lang <lang> --mode <full|quick>` + `--pdf`, `--scores` по флагам прогона. `--css` не нужен: без него `report.mjs` сам берёт `report_css` из настроек. `--title` и `--logo` передаёшь, только если оркестратор дал их значения отдельной строкой промта. Код 75 — повтори ту же команду. Код 2 — не хватает файла (вывод скажет какого).
- **[editor-39]** Код 1 — ошибки самопроверки в `report/selfcheck.json`. Что делать по правилу:

| `rule` | Правка |
|---|---|
| `summary` | нет `report/summary.json` или он не разбирается: запиши и прогони `validate.mjs` |
| `counts` | `summary.counts` = числа `finalize.mjs` |
| `refs` | номер, которого нет в отчёте: поправь `summary` или текст находки |
| `confirmed` | подтверждённая находка потерялась: поправь `merge`/`drop`, снова `finalize.mjs` |
| `rid` | номера повторяются в `findings.json`: снова `finalize.mjs` |
| `textscan` | маркер нейрослопа P0–P1 в тексте отчёта: перепиши поле (`rewrite` или `summary`) |
| `forbidden` | слово из запрет-листа аудитории: перепиши поле (адрес поля — в `where`: `P1-04 fix`, `P1-04 evidence`, `summary.essence[2]`) |
| `external` | следы набора в тексте для чужой команды: перепиши |
| `edits` | ошибка в `report/edits.json` (правки по комментариям получателя): номер или фраза не найдены — сообщи оркестратору, файл пишет он |
| `pdf` | лист PDF больше A4 или PDF не собрался: повтори один раз, не помогло — сообщи оркестратору |
| `status` | статус в `--status` не из списка или нет такой находки/uid: повтори `report.mjs --status "P0-01=в работе"` с одним из четырёх: новое / в работе / исправлено / не будем исправлять |
