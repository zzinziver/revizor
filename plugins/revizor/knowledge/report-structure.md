# Структура отчёта

Для редактора (`editor`), оркестратора и критика. Отчёт собирает скрипт `report.mjs` из данных; редактор пишет данные (`editorial.json`, `summary.json`), смотрит кадры готового отчёта и правит. Тон и запреты — `tone.md`.

## 1. Что получает человек

| Файл | Когда | Кому |
|---|---|---|
| `report/report.html` | всегда | один файл: картинки внутри, без скриптов, тёмная тема, печать |
| `report/registry.xlsx` | всегда | реестр замечаний для разработчика (§8) |
| `report/report.pdf` | `--pdf` | тот же HTML, листы A4, вёрстка без артефактов на iPhone (§9) |
| `report/report-files/` + `.zip` | HTML вышел больше 15 МБ | версия с папкой картинок |
| `report/rivals.html`, `rivals.xlsx` | `/revizor:rivals` | галерея конкурентов, матрица, лучшее, идеи |
| `report/recheck.html`, `registry-recheck-<дата>.xlsx` | `/revizor:recheck` | итог проверки правок; входной реестр не перезаписывается |

В чат после отчёта — 5–8 строк: вердикт, числа по важности словами аудитории, три главные проблемы, абсолютные пути к отчёту и реестру, размер папки, подсказка про `/revizor:recheck` и `/revizor:rivals`.

## 2. Из чего собирается

| Источник | Кто пишет | Что даёт |
|---|---|---|
| `report/findings.json` | `finalize.mjs` из `candidates.json` и `editorial.json` | находки с номерами `rid` (P0-01…) и постоянным `uid` |
| `report/summary.json` | редактор | всё, что выше карточек: суть, светофор, первые действия, развилки (§5) |
| `report/scores-strict.json`, `scores-market.json` | `scorer` при `--scores` | оценки двух комиссий |
| `report/strategy.json` | `strategist` при `--strategy` | планы SEO и развития сайта |
| `report/edits.json` | оркестратор по комментариям получателя | правки отчёта (§11) |
| `report/diff.json` | `quick health` | что появилось и что исправлено с прошлого прогона |
| `brief.json` | `scout` | вопросы владельца В1…Вn, аудитория, язык, платформа |

## 4. Объём

- Владельцу в теле — не больше 30 карточек P0–P1. P2–P3 — таблицами в свёрнутых блоках, полностью — в Excel. Полное ревью даёт 100–300 находок; длинный список карточек подряд владелец не дочитывает.
- `essence`: 3–6 выводов, в каждом цифра; первый — главное для бизнеса.
- `top_actions`: порядок «внешнее и доступы → P0 → быстрые победы → остальное», до 10 строк.
- `quick_wins`: до 10 номеров (S при P1–P2, без решения владельца).
- `strengths`: до 6, с доводом и цифрой (`severity.md` §10).
- `device_checks`: до 10 (`human-checks.md`).
- `decisions`: вопрос, 2–3 варианта, рекомендованный первым со ★, ссылки на номера.
- Для чужой команды мелкие правки идут **все** (приложение «Мелкие правки»), лимиты P3 у `copy` и `typography` сняты.

## 5. Что редактор пишет в `summary.json`

```json
{ "title": "Ревью сайта кофейни", "site": "https://example.ru/", "date": "ДД.ММ.ГГГГ", "audience": "owner", "lang": "ru", "mode": "full",
  "verdict_line": "Сайт продаёт кофе с собой, но с телефона заказать нельзя: кнопка меню не нажимается",
  "essence": ["С телефона заказ недоступен: меню на 390 px закрыто прозрачным слоем (P0-01)", "…"],
  "goals_answers": [ { "id": "В1", "answer": "…" } ],
  "traffic_lights": [ { "area": "Мобильная версия", "status": "red", "line": "меню не нажимается, страница «Меню» уезжает вбок" } ],
  "top_actions": [ { "rid": "P0-01", "action": "…", "why": "…", "who": "разработчик" } ],
  "quick_wins": ["P1-03"], "strengths": [ { "what": "…", "why": "…" } ],
  "decisions": [ { "question": "…", "options": ["★ …", "…"], "rids": ["P2-04"] } ],
  "device_checks": ["iPhone, Safari: …"], "owner_todo": ["…"], "not_checked": ["…"], "method": "…", "external_services": [],
  "rivals_compared": [ { "url": "…", "why": "…" } ], "memory_applied": 0,
  "counts": { "P0": 0, "P1": 0, "P2": 0, "P3": 0 }, "process": { "found": 0, "confirmed": 0, "adjusted": 0, "rejected": 0, "unverified": 0, "rounds": 1 } }
```

- `verdict_line` — одно предложение: что за сайт и главное, что мешает.
- `goals_answers` — ответ на каждый вопрос владельца В1…Вn из брифа, одной строкой со ссылкой на номера.
- `traffic_lights` — 6–10 разделов: `red` (есть P0 или ≥ 3 P1), `yellow` (есть P1 или много P2), `green` (только P3 или ничего).
- `counts` — после слияния и снятия; скрипт сверяет их с `findings.json`.
- `method` — для чужой команды одна фраза: «Мы проверили 20 страниц на телефоне и компьютере, формы не отправляли».
- Номера `rid` в тексте должны существовать в этом отчёте (самопроверка ловит ссылки на снятые и перенумерованные).

## 6. Карточка находки

| Поле карточки | owner | team | external |
|---|---|---|---|
| Важность, номер, кто, объём | да | да | да |
| Заголовок (`title`) | да | да | да |
| Где: страница, блок, ширина, состояние | да | + селектор | да |
| Что не так (`problem`), Факт (`evidence`), Почему важно (`impact`), Как исправить (`fix`) | да | да | да |
| Сценарий (`scenario`) | нет | да | нет |
| Было → стало (`before`/`after`) | да | да | да |
| «Правку проверили подменой» | да | + как (`fix_check`) | да |
| Метки «Нужно ваше решение», «Проверьте на устройстве», «Требует проверки» | да | да | только «решение» |
| Чем проверено, норма, перепроверка | кратко | + уверенность, линзы, история важности, `uid` | только норма, понятная людям (WCAG, закон) |
| Кадры: до 2 кропов с рамкой | да | да | да |

«Факт» (`evidence`) устроен из двух частей: факт словами и источник в конце в квадратных скобках — «Таблица цен на 360 px выходит за край на 64 px [measure/mobile.json → overflow 64 px @360]». Своей команде и владельцу показываются обе части. Чужой команде — только факт: техническую часть в скобках `report.mjs` отрезает и в карточке, и в самопроверке.

Если в факте вне скобок остались файл, поле или команда, `report.mjs` в отчёте для чужой команды прячет факт этой карточки и пишет предупреждение со списком номеров. Редактор переписывает `evidence` через `rewrite` (только сократить или переформулировать, без новых цитат и чисел — `finalize.mjs` проверяет). Линзы сдают `evidence` сразу в этом формате (`core.md` §6, `findings-format.md` §6).

## 7. Режимы

- **full** — всё по §3.
- **quick** — одна тема: суть, карточки, остальное таблицей, реестр. Без стратегий, без оценок. `health` — без линз: коды, сертификат, домен, robots и sitemap, title и description, разметка, вес и LCP главной, ошибки JS, новые поддомены + «Что изменилось» против прошлого прогона хоста («первый снимок», если сравнивать не с чем).
- **rivals** — `rivals.html`: плитки свода «у N из M» дословно, направления с эскизами, топ-10 идей, карточки по типам блоков, галерея; отметки «беру / нет / обсудить» и кнопка «Скопировать мои решения» (единственный скрипт в отчётах). Без оценок.
- **recheck** — `recheck.html`: по каждой прошлой находке статус (исправлено, частично, не исправлено, стало хуже, неприменимо, не удалось проверить) с доказательством и кадром «было / стало», отдельно регрессии и новые находки; новый реестр со столбцами «Проверено ДД.ММ» и «Итог перепроверки».

## 8. Реестр `registry.xlsx`

- Лист «Замечания», ровно эти колонки по порядку: `№ | Важность | Раздел сайта | Тема | Что на сайте | Где (URL · блок) | Как исправить | Кто | Трудоёмкость | Статус | Комментарий | Проверено`. Для `team` в конце: `Линзы | Метод | Норма | Уверенность | uid`.
- «Статус» — список: новое / в работе / исправлено / не будем исправлять. «Не будем исправлять» с комментарием попадает в `site-memory` и больше не предлагается.
- Лист «По месту правки»: группы по `fix_place` (шаблон, общий CSS, блок CMS, настройки платформы, сервер, контент, внешний сервис) и «как проверить».
- Лист «Сводка» — формулами (числа по важности и статусам). Лист «Как читать».
- Скрытый лист `_revizor`: `uid | rid | url | selector | viewport | state | method | lens | norm` + строка мета. Для чужой команды в нём нет путей к файлам и кодов агентов.
- Номера в реестре совпадают с номерами в HTML. Реестр, пересохранённый в Excel или LibreOffice, читается `recheck` по заголовкам столбцов.

## 9. PDF

- Тени только плоские (размытие 0), фоны сплошным цветом без прозрачности, без `mix-blend-mode`, лист не выше A4, карточки не рвутся между листами. Размытую тень PDF на iPhone рисует сплошным прямоугольником.
- Редактор смотрит каждый лист PDF как картинку (`report/shots/report-pdf.part-NN.jpg`): пустые низы, оторванные заголовки, таблицы за краем.

## 10. Внутренний слой

- Всё в RUN, кроме `report/`, — рабочие файлы: `findings/`, `verify/`, `critic/`, `notes/`, `measure/`, `snapshot/`. Получателю не передаются.
- После успешного отчёта (без `--keep-raw`) удаляются куски кадров `*.part-NN.jpg`, `dom.html`, промежуточные кадры `mobile/`, `collect/`, кадры `inner`. В чат — размер папки.

## 11. Правки отчёта по комментариям получателя

- `report/edits.json`: `[{ "op": "drop|severity|replace_text", "rid", "field", "from", "to", "why", "scope": "one|all" }]`. Правило из одного комментария (`scope: "all"`) применяется ко всем находкам той же темы (`category`).
- `report.mjs --renumber` перенумеровывает и пишет `renumber.json` (старый номер → новый); итоги считаются заново.

## 12. Самопроверка и просмотр

`report.mjs` после сборки проверяет: все `rid` есть в HTML и XLSX; числа совпадают с `summary.counts`; подтверждённые находки не пропали; язык отчёта (`textscan --report`) без P0–P1; нет слов из запрет-листа аудитории (`tone.md`, раздел «Запрещено»; цитаты в кавычках и код не проверяются); для чужой команды — ещё пути, коды линз, хэши, даты прогона, оценки (в `evidence` — вне части в скобках); нет `<script` и обработчиков событий из данных. Ошибка самопроверки — редактор правит данные и собирает заново (до 2 раз).

Редактор смотрит **все** куски отчёта на 390 и 1440 px (`report/shots/report-390.part-NN.jpg`, `report-1440.part-NN.jpg`) и тёмную тему: переполнение таблиц, пустые блоки, оторванные заголовки, нечитаемые кропы.
