# Профиль `strict` — строгий вкус

**Сначала прочитай `profiles/standard.md`: этот профиль добавляет правила поверх него. Где правила расходятся, прав этот файл.**

Включается `--profile strict` или настройкой `profile: strict`. Это правила заказчика с сильным вкусом: тексты без оговорок, дизайн «не хуже лучших в нише», варианты правок картинками, разбор правок по одной.

**Ревизор ничего не меняет на сайте.** «По одной» в этом профиле — формат разбора готового отчёта с владельцем.

## 1. Как применять

- Правило профиля — объявленное требование заказчика ревью. Нарушение — находка с `taste: false` и тегом `profile:strict`. Важность — по таблице ниже; P1 — только если нарушение в первом экране главной или посадочной и мешает действию.
- Решения владельца сайта (`owner_decisions`, `do_not_suggest`) сильнее профиля: отклонённое не всплывает ни находкой, ни развилкой.
- Правило профиля не перекрывает норму: контраст, доступность, факты, закон проверяются по общим правилам.
- Где правило требует вариантов (шрифт, палитра, раскладка), находка идёт с `needs_decision: true`, варианты — кадрами (D12), рекомендованный первым со ★.

## 2. Тексты сайта

| № | Правило | Линза | Важность |
|---|---|---|---|
| S1 | Никаких оговорок и сомнений о продукте: «если товара не окажется на складе», «ответим, если сможем помочь», «обычно» перед сроком, «к сожалению», «по возможности». Сноска, которую владелец поставил сам («доставка за 2–3 дня*» с пояснением внизу), — не оговорка | copy | P2; в первом экране и у кнопки — P1 |
| S2 | Диапазоны словами: «от 2 до 3 дней» вместо «2–3 дня» | copy | P3 |
| S3 | Утвердительный тон о продукте. Промежуточных статусов «проверим», «уточним», «сверим» в тексте сайта нет | copy, facts | P2 |
| S4 | Главный маркер нейрослопа — «не X, а Y». Дальше: триады ради ритма, канцелярит, «давайте», «важно отметить», «реально», набор фраз под поисковые запросы | copy | «не просто X, а Y» — P1 везде; общий «не X, а Y» и остальное — первый экран P1, ниже P2 |
| S5 | Текст о продукте — литературным языком в третьем лице, без разговорного «у нас» и интонации личного сообщения | copy | P3 |
| S6 | Без простыней: мини-карточки, цифры, фото, короткие подписи. Плотный абзац длиннее 4 строк на 390 px — дефект. Поясняющая строка — наверху и крупно | copy, visual | P2 |
| S7 | Имена владельцев и сотрудников не видны в коде и текстах, если они об этом не просили | stability, legal | P2 |

## 3. Дизайн

| № | Правило | Линза | Важность |
|---|---|---|---|
| D1 | Планка «не хуже лучших в нише»: в каждом блоке своя картинка или живая анимация. «Бедновато» — дефект, но только с кадром конкурента из `rivals/` | visual, product | P2 |
| D2 | Глубина важнее количества: мало блоков, каждый доведён. Незавершённое — за аккуратной пометкой «скоро» с тизером; заглушка без пометки читается как финальный уровень | visual | P2 |
| D3 | Шрифты «по умолчанию у нейросетей» под запретом: Inter, Manrope, Montserrat, Unbounded, Golos, Onest, Roboto, Rubik, Nunito, Space Grotesk, IBM Plex, Geist, JetBrains Mono, Plus Jakarta Sans, DM Sans, Poppins; Playfair Display в паре с гротеском из списка. В правках их не предлагать; вместо них — 2–3 непривычных шрифта с кириллицей, показанных картинкой (D12). Проверка — `typography-36` | typography | P2, `needs_decision` |
| D4 | Палитра «тёмно-синий + коралл + янтарь + крем» без опоры на материал проекта — палитра из генератора; так же кремовый фон + засечки + терракота, олива или шалфей, фиолетово-синий градиент в первом экране, почти чёрный фон + неон. Палитру выводить из фото проекта и брендбука. Проверка — `color-35` | color, visual | P2, `needs_decision` |
| D5 | Интерфейс «из коробки» — дефект: пилюли-чипсы, плашки меню с рамками, серые кнопки-овалы, моноширинный капс в надзаголовках. Приметы с замером — `visual-52` | visual | P2 |
| D6 | Живые фото важнее сгенерированных; декор поверх фото не налеплять | visual | P2 |
| D7 | Кнопка в карточке — внизу; под кнопками первого экрана текста нет; карточка без цвета на фоне секции — со светло-серой рамкой 1 px | visual | P3 |
| D8 | Паттерны главной не ломать: новая страница повторяет механики главной (свои попапы, карточки, декор); одна механика на странице — один раз | visual, ux | P2 |
| D9 | Одна задача на страницу; главная не копирует разделы; уводящие ссылки (в соцсеть, «к посту») — только где без них нельзя | product, ux | P2 |
| D10 | Сайт светлый — тёмную тему не требовать; кадры вариантов — в светлой теме | color | — |
| D11 | «Уменьшить» — та же раскладка мельче. Новую раскладку предлагать развилкой с кадрами. Слабую или дублирующую кнопку — предлагать убрать; перекрашивать её бессмысленно | visual, product | — |
| D12 | **Варианты видимой правки — картинками.** Каждый вариант снимается подменой на настоящей странице с настоящими шапкой и подвалом: `probe --pid <pid> --width 390 --css "<RUN>/probe-js/<id>-a.css" --shot <id>-a-390.jpg`, то же на 1440, в светлой теме. Кадры кладутся в `where` отдельными местами (`state: "вариант А ★"`, `shot: "probe/<файл>"`, те же `pid` и `url`): первым — текущий вид, вторым — рекомендованный вариант (в карточку отчёта идут два кадра). В `fix` — варианты словами со ссылкой на кадры. Вариант без кадра — не вариант. Шрифты — лист из 2–3 гарнитур на одном тексте сайта | visual, typography, color, product | как у находки |
| D13 | У каждой анимации есть ответ «зачем»: показывает связь, обратную связь или порядок. Движение ради движения — дефект | visual | P3 |
| D14 | Шаблонный вид «как у сайтов из генератора»: каждая примета из `visual-52` (палитра — `color-35`, шрифты — `typography-36`, «стекло», бенто, мягкие одинаковые карточки, «три иконки в ряд», пилюля над H1, эмодзи и стандартные контурные иконки, свечения и градиентные рамки, одинаковые центрированные секции, абстрактные блобы) — отдельная находка своей линзы с кадром и полем замера; сводной нет. В отчёте — «шаблонный вид», без «сделано нейросетью» | visual, color, typography | P2 за примету |

## 4. Важность правок главной

Переписывание главной сверх фактических ошибок — оффер первого экрана, порядок блоков, FAQ, шрифт, цвет брендовых кнопок, состав подвала — P3 с `needs_decision: true`: решение владельца.

Это правило не понижает поломку пути к действию: нет кнопки действия, кнопка не нажимается, оффер не назван вовсе, за 5 секунд непонятно, что продают, — важность по `severity.md` (P0–P1). Понижается только переделка того, что работает.

Обычной шкалой идут: фактические ошибки (цены, адреса, сроки), невидимая техника (viewport, разметка, крошки, alt, Clean-param), скорость главной, перелинковка, кнопка действия на телефоне — такое владельцы почти всегда принимают.

## 5. Проверки к каждой видимой правке

Владелец этого профиля ловит руками то, что пропустила проверка. Поэтому к каждой находке с правкой CSS или HTML, не только P0–P1:
- подмена на 390 и 1440 на настоящей шапке и подвале (D12);
- правка шапки — ещё бургер на 375 и 834: открывается касанием, пункты нажимаются, меню закрывается;
- любая CSS-правка — ещё переполнение на 320 и 440 (`documentElement.scrollWidth` не больше ширины окна);
- правка меню — активный пункт виден на странице, куда ведёт этот пункт;
- мобильная версия — кадры до низа каждой затронутой страницы: одиночный элемент после кнопок, налезания, пустые хвосты;
- в `fix_check` — все ширины и итог по каждой.

Для `recheck` после публикации: CDN несколько минут отдаёт то старую, то новую версию. Перемер — когда на странице уже виден новый код; иначе `not_fixed` будет ложным.

## 6. Процесс (оркестратор, редактор)

- Вопросы — всплывающим окном, **по одному**, с конкретными вариантами; рекомендованный — первым и со ★. Перед вопросом о видимом — картинка (кроп с рамкой или кадры вариантов).
- Мелкие решения по ходу ревью (какую страницу досмотреть, какую ширину добавить) оркестратор принимает сам и сообщает одной строкой. Всё, что меняет структуру сайта, обещания клиенту, цифры, — вопросом.
- Ответы, которые уже есть в брифе, настройках и `site-memory`, не спрашивать повторно.
- Оценки: владельцу этого профиля они нужны для сравнения сайтов между собой — включаются флагом `--scores` или настройкой `scores: true`. В документе для чужой команды оценок нет и здесь.
- После отчёта — разбор топа P0–P1 по одному: кроп или кадры вариантов → вопрос «Берём / Не будем / Отложить» (рекомендованный первым со ★) → статус в реестре («в работе», «не будем исправлять») и в `site-memory` («Берём» → `memory.mjs --add known --text-file … --uid <uid>`, «Не будем» → `--add do_not_suggest --text-file …`; готовую команду даёт `state.mjs --next`, текст — только файлом). Следующий пункт — после ответа на предыдущий.
- Исследований сверх заказанного не запускать; проверенное не перемеривать; тяжёлые прогоны — только по нужде. Заказчик следит за расходом лимита.
- Пользоваться установленными навыками по языку и SEO и коротко называть, какой взят (`skills_used`).
- Документ для чужой команды от имени заказчика: все недочёты без исключения, даже лишний пробел, но обезличенно; темы, которые заказчик придерживает (`do_not_touch`), не подсвечивать без вопроса; заявления о льготах — уточнять.

## 7. Чем отличается от `standard`

| Тема | `standard` | `strict` |
|---|---|---|
| Оговорки в текстах сайта | P3, если не трогают главное обещание; в первом экране — P2 | S1: P2, в первом экране — P1 |
| Диапазоны «2–3 дня» | норма | S2: словами, P3 |
| Простыни | длинный абзац — P3 | S6: дефект, P2 |
| Шрифты и палитры | нормы (кириллица, кегль, контраст, лицензия); шрифты и палитры из списков генераторов — примета P3 (`typography-36`, `color-35`); остальной выбор — вкус P3 | D3, D4: P2, запрет-лист и вывод из материала |
| Шаблонность, «из коробки» | приметы `visual-52` — P3 за каждую, от 3 примет — сводная P2; остальное — `taste`, P3 | D5, D14: P2 за каждую примету |
| «Бедновато» | `taste`, P3; «ниже ниши» — с кадром конкурента | D1: дефект P2 с кадром конкурента |
| Анимация | техника: `transform`, `opacity`, «уменьшить движение» | D13: ещё и ответ «зачем» |
| Варианты правки | текстом в `fix` | D12: кадрами подмены на 390 и 1440 |
| Проверка правки подменой | P0–P1 | каждая правка CSS или HTML (§5) |
| Изменения главной | по влиянию | переделка работающего — P3 и решение владельца; поломка пути к действию — обычной шкалой |
| Вопросы | одно окно, до 4 вопросов | по одному, с картинкой |
| После отчёта | итог в чат | разбор топа P0–P1 по одному |
